# Правила работы · разработчик

Обязательные правила для **людей и ассистентов** в роли разработчика (03).

---

## 1. После изменения фронта — сборка

Любые правки в **`_telotron.ru/resources/ts/`**, **`resources/css/`**, Vite-конфиге, PWA/SW, `public/` assets, затрагивающие prod-бандл — **завершать сборкой фронта** в том же изменении (или явно указать, что сборка не нужна, если правка только в dev-only).

**Команда** — только из каталога **`_telotron.ru/`**, только в контейнере, **от пользователя `sail`**:

```bash
cd _telotron.ru
docker compose exec -u sail laravel.test npm run build
```

Не запускать `npm` / `vite` на хосте. Не собирать от root (без `-u sail`) — иначе `public/build/` уйдёт под root и сломаются права.

После ошибочной root-сборки: один раз удалить `public/build` от root, затем пересобрать под `sail` (см. [локальная среда Docker](../../../_telotron.ru/docs/Техдок/04-платформа-и-эксплуатация/локальная-среда-docker-nginx.md)).

**Проверки по ситуации:** `npm run test:ts`, `npx tsc --noEmit` — тоже только через `docker compose exec -u sail laravel.test …`.

---

## 2. Не запускать субагентов

**Ни в коем случае** не вызывать субагентов (Task tool, explore/generalPurpose/shell subagents, Bugbot, security-review и т.п.) в работе по этому проекту.

Вся работа — **в текущей сессии**: читать код, править файлы, запускать команды напрямую. Делегирование фоновым агентам **запрещено**.
