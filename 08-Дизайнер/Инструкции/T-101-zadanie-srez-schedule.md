## 2. Scope (делать)

### 2.1. Имя и шапка

- H1 / tab: **Расписание** (не «Календарь»).
- CTA **«+ Занятие»** (или текущий «Новое занятие») — компактно в шапке, не отдельной простынёй.
- Убрать лишний lead про «только онлайн», если offline уже в shell-banner.
- Навигация периода: ‹ › + **«Сегодня»**; подпись окна дней (напр. `Пн 28 – Ср 30 июл`).

Wireframe: §3.1.

### 2.2. Сетка дни × часы (основной вид)

| Параметр | Канон |
|----------|--------|
| Ось X | Дни |
| Ось Y | Часы |
| Колонок дней | **Отзывчиво:** ~360→**3**, ~600→**5**, ~900+→**7** (breakpoints уточнить на 360/430/tablet) |
| Сдвиг окна | стрелки / жест; якорь «сегодня» |
| Высота часа | фиксированная (~40–48px); **вертикальный скролл** |
| Ось часов | из **«Мои часы»**; иначе **07:00–22:00** |
| При открытии | скролл к **сегодня** + **текущему часу** (или ближайшему слоту, если «сейчас» вне оси) |
| Линия «сейчас» | на колонке сегодняшней даты |

**Слот занятия:** цвет/тип как сейчас (individual/group); на узкой колонке — короткое имя или инициалы; тап → детали/edit.

**Пустая ячейка:** online → create на это время (если уже есть в продукте) или фокус на «+».

**Старый toolbar** agenda / day / week / month как **равноправные** режимы — **убрать** с основного UX. Допустим позже отдельный «список дня» как secondary, не в MVP этого задания.

Wireframe: §3.2.

### 2.3. «Мои часы» в профиле

- В **Профиле** (Кабинет + аватар в шапке → один экран): блок **«Мои часы»** — начало и конец рабочего дня.
- Пока не задано → сетка использует **07:00–22:00**.
- Persistence: поле профиля / settings — **с архитектором** (не блокер UI-макета; можно local/API stub с TODO, но целевое — сервер).

Wireframe: §4.2.

### 2.4. Empty / offline

- Нет занятий в окне — спокойный empty + CTA создать.
- Offline: один banner shell; слоты read-only как сейчас по политике продукта.

## 6. Риски / вопросы

1. Persistence «Моих часов» — схема API.  
2. Производительность сетки при многих слотах (виртуализация later).  
3. Миграция пользователей с persisted `mode=week|month` — сброс на сетку.  
4. Query `?create=1&client_user_id=` (из hub) должен открывать create поверх/рядом с сеткой.
