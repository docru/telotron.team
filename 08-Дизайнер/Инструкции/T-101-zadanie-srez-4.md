## 2. Scope (делать)

### 2.1. Client главная (A5)

Слои сверху вниз:

1. **Прогресс за неделю** — одна строка активности за 7 дней.  
2. **Ближайшее занятие** — только если есть; иначе блок не показывать.  
3. **Плитка «Прогресс»** (крупнее) → `workspace-measurements`.  
   - Мини-график **веса**: если **≥3** точек — **последние 3**; иначе без графика.  
4. **Компактный ряд:** Тренировки · Питание · Трекеры (дублируют bottom tabs намеренно).

**Не на главной:** Поддержка, Профиль, полный дашборд виджетов, большой график.  
**Не** добавлять 5-й таб «Прогресс».

Bottom tabs Client **без изменений состава:** Главная · Тренировки · Питание · Трекеры.

Wireframe: §5.

### 2.2. Client дневник — вид (A7)

Единый chrome для Тренировки / Питание / Трекеры:

- Основной вид — **день**.  
- Сверху — **полоска дат текущей недели** (как уже в питании/трекерах — унифицировать).  
- Дата **без записей** — визуально приглушена, но тапабельна → в теле дня empty: «В этот день записей нет».  
- Убрать как основной UX: сегмент режимов agenda / day / week / month на Client-дневниках.

Wireframe: §6.

### 2.3. Словарь (A7)

| Сущность | Label |
|----------|--------|
| Занятия тренера | **Расписание** (Pro; если в этом срезе ещё мелькает «Календарь» в Client-копи про занятия — поправить) |
| Фиксация клиентом | **Дневник** / **Дневники** |

- Вкладки/экраны Client: **не** «Календарь» для ленты дневника.  
- Voice + route meta + UI labels в одной линии.

### 2.4. Nutrition default (A6)

Если не закрыто в срезе 1: `/nutrition` без `?sub=` → **дневник** (`diary`), не calendar.

### 2.5. Empty / error / offline (A8)

На ключевых экранах Client (+ пересечение с уже тронутыми Pro, если дыры):

| Состояние | Паттерн |
|-----------|---------|
| Empty | фраза + **next-step CTA** |
| Error | текст + «Повторить» |
| Offline | один banner shell; не три текста на странице |

Минимум: Client home, хабы дневников; по возможности — стык с Клиенты/Расписание/Hub если уже в коде после срезов 1–3.

Wireframe: §7.
