## 2. Scope (делать)

### 2.1. Слои сводки (сверху вниз)

1. **Кто:** имя, аватар, возраст / ДР (как сейчас по смыслу).  
2. **Ближайшее занятие:** `Ближайшее: ср 18:00` — info, тап → детали/редактирование. Не бог-primary всего экрана. Нет занятия → «Нет ближайших занятий».  
3. **Неделя:** **одна строка** за 7 дней, вроде  
   `3 тренировки · питание 5/7 · вес обновлён`  
   Нет данных → «Пока мало данных». Не дашборд из 3–4 карточек.  
4. **Плитки действий** (с подписями):  
   - Записать на занятие → create в расписании с этим клиентом  
   - Тренировки → назначения  
   - Питание → назначения / дневник  
   - Трекеры  
   - Прогресс  

Допустимо чуть выделить «Записать на занятие» среди плиток — **не** единственная кнопка на весь экран.

### 2.2. Навигация после плитки

- Тап → экран детали с **«Назад»** на сводку.  
- Подвкладки внутри детали — ок по необходимости.  
- **На входе hub запрещено:** два ряда табов (секция + подвкладка), как сейчас 4×2.

### 2.3. Данные строки «неделя»

- MVP: собрать из уже доступных API/фидов (тренировки / питание / трекеры / вес), что есть.  
- Точная формула сегментов — с PO при дырах в данных; empty-строка обязательна.  
- Не блокировать UI ожиданием идеальной аналитики.
