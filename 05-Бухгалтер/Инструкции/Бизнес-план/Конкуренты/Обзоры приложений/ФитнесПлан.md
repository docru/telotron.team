## Что понравилось (директор)

| # | Что | Почему важно | Действие для нас |
|---|-----|--------------|------------------|
| 1 | **Программный datepicker** | Год → месяц → день; кастомный UI, не native | Сверить с нашим ДР/датами; при слабом UX — взять паттерн |
| 2 | **Схема тарифов тренера для клиентов** | Гибко: разовая / дни / недели / месяцы / **тренировки** | Кандидат для учёта оплат Client→тренер (A2); не путать с тарифами платформы |
| 3 | **База готовых упражнений** | Сразу можно собирать программы | Усилить каталог / сиды упражнений |
| 4 | **Группы мышц** (агонист / синергист) | Нормальная разметка базы | В модели упражнений — теги мышц |
| 5 | **GIF / видео** на упражнении | Техника «из коробки» | Связь с идеей видео в PWA; upload + ссылка |
| 6 | **Страница финансов** | Учёт: месяц, всего, к оплате, просрочки, истекающие | Дашборд учёта без эквайринга — эталон простоты |

### Не преимущество / слабее нас

| Тема | ФитнесПлан | Вердикт директора |
|------|------------|-------------------|
| Регистрация клиента | Тренер вводит имя+email+ДР → аккаунт; **или** ссылка; логин на email | **У нас лучше**; чище с т.з. **ПД** (клиент сам вводит данные) |
| Ссылка на регистрацию | **Каждый раз новая** | Пока **не видно преимущества** |

**Итог прохода:** кроме пунктов выше — **больше ничего интересного** не нашёл.

## Наблюдения прохода 1 (2026-07-23)

### 1. Datepicker

([02–04](скрины/ФитнесПлан/02-datepicker-год.png))

Программный (не native): сначала **декада/год**, затем **месяцы**, затем **календарь дней**. Нравится — контролируемый UX для ДР.

### 2. Добавление клиента

([05-добавить-клиента.png](скрины/ФитнесПлан/05-добавить-клиента.png))

Два режима:

| Режим | Суть |
|-------|------|
| **Зарегистрировать** | Тренер заполняет имя*, email*, опц. ДР/пол; аккаунт создаётся; **данные для входа на email** |
| **Ссылка** | Клиент регистрируется сам |

При регистрации сразу блок **«Тариф»** (тариф сопровождения клиента) — «создать первый».

**ПД:** тренер вводит email/ДР клиента до согласия клиента — слабее модели Telotron (инвайт → клиент сам заполняет).

### 3. Тарифы тренера для клиентов (не подписка платформы)

([06–07](скрины/ФитнесПлан/06-новый-тариф-форма.png))

Форма «Новый тариф»:

- Название*, описание, цена*, валюта (RUB)
- **Единица:** разовая / дней / недель / месяцев / **тренировок**
- Количество* (напр. 1 месяц; месяцы учитывают 28–31 день)
- Чекбокс «Активен (можно назначать клиентам)»

Гибкая модель учёта абонементов клиента — **нравится**.

### 4. Упражнения

([08–09](скрины/ФитнесПлан/08-упражнения-список.png))

- Готовая **база** (бег, планка, жим…) + свои
- Колонки: название, **группы мышц** (теги), оборудование, единицы (дистанция / время / повторы+вес), видео
- Создание: метрика, вес снаряда, **upload видео/GIF** или ссылка, оборудование, мышцы **агонист / синергист**

### 5. Финансы

([10-финансы.png](скрины/ФитнесПлан/10-финансы.png))

Дашборд учёта (без приёма денег платформой):

- В этом месяце / всего / к оплате / активные тарифы
- График дохода за 6 мес.
- Просроченные / скоро истекает
- Последние платежи
- «Управлять тарифами»

## Вердикт (проход 1)

**Итог:** узкий, но аккуратный продукт для **онлайн-программ + учёт оплат**. Сильные куски: **каталог упражнений**, **тарифы сопровождения**, **финансы**, datepicker. Слабее нас по инвайту/ПД; нет питания и «полного дня». Директор: кроме отмеченного — **мало интересного**.

**Заимствовать:**

1. Модель **тарифа клиента** (единица × количество, в т.ч. «тренировок»).
2. Дашборд **учёта финансов** (просрочки / истекающие).
3. База упражнений + **группы мышц** + GIF/видео.
4. UX datepicker (если наш хуже).

**Не копировать:** создание аккаунта клиента тренером с email (ПД); «новая ссылка каждый раз» без явной выгоды.

**Чем бить:** Лайт без квоты; питание + календарь/группы; чистый инвайт.

**Приоритет мониторинга:** средний–высокий (цена + программы).
