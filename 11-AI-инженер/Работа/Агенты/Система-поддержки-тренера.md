# Поддержка тренера: идея и фундамент для MVP

## Что это

**Поддержка** — это сквозной параметр системы, который определяет, **сколько и какой поддержки** система оказывает тренеру в данный момент. Не «мотивация» (воздействие на состояние), а **поддержка** (помощь в действии).

**Зачем:**
- Для тренера — снижение тревоги, признание прогресса, уместное внимание к состоянию
- Для продукта — удержание через доверие, а не через манипуляцию

**Ключевой принцип:** поддержка **калибрована** под профиль тренера и его текущее состояние. Не навязывается, а соответствует. Тренер контролирует потолок.

**Чего система НЕ делает:**
- Не имитирует эмоции
- Не мотивирует словами («ты справишься», «не сдавайся»)
- Не давит
- Не использует поддержку для удержания
- Не повышает уровень без согласия тренера

## Как это работает

### Температура поддержки

Градуированная величина от 0 до 4:

| Уровень | Что делает система | Пример |
|---|---|---|
| **0** | Только факты и задачи | «Задача: ответить Анне» |
| **1** | Признание прогресса | «За неделю — 5 ответов, 3 диалога» |
| **2** | Внимание к состоянию | «Ты отложил эту задачу трижды. Может, убрать?» |
| **3** | Активная поддержка | «Ты давно не отдыхал. Предлагаю паузу на завтра» |
| **4** | Деликатный разговор | «Ты не заходил неделю. Всё в порядке?» |

### Из чего складывается

| Компонент | Источник | Влияние |
|---|---|---|
| **Базовая** | Профиль тренера | Стиль, отношение к поддержке, предпочтения |
| **Корректировка состояния** | Логи | Откладывания, паузы, реакции на подсказки |
| **Корректировка контекста** | Ситуация | Провал стратегии, много отказов, первая неделя |
| **Потолок** | Настройки тренера | Максимум, выше которого система не поднимает |

### Кто управляет

**Код, не ИИ.** Температура вычисляется по правилам. ИИ используется только для **формулировки** поддержки в стиле тренера.

### Контроль тренера

- **Явно:** в настройках — «Уровень поддержки: низкий / средний / высокий»
- **Неявно:** через реакции — «спасибо, не нужно» → температура падает
- **Прозрачно:** тренер может посмотреть текущую температуру и почему она такая

## Что закладывается в MVP

Поддержка **не реализуется** в MVP. Но **фундамент** закладывается — потому что дёшево сейчас и дорого потом.

### 1. Параметры профиля в анкете

| Что спрашиваем | Зачем |
|---|---|
| Стиль общения | Для формулировок |
| Отношение к поддержке | «Не надо меня мотивировать» — потолок |
| Предпочтения | Что помогает: факты, примеры, разговоры |
| Границы | Что не хочет слышать |

**Стоимость сейчас:** 4–5 вопросов в анкете.
**Без этого потом:** переделка анкеты + миграция данных.

### 2. Видимый прогресс в брифе

Не поддержка, а **факты**. Ценно само по себе.

- «За неделю — 5 ответов, 3 диалога»
- «Ты освоил реактивацию»
- «Стратегия работает: критерий достигнут»

**Стоимость сейчас:** один блок в брифе на основе `metrics_daily`.
**Без этого потом:** нет основы для поддержки.

### 3. Поля для сигналов состояния в логировании

| Поле | Зачем |
|---|---|
| `care_temperature` | Текущая температура (пока 0–1) |
| `state_signals` | Сигналы состояния (откладывания, паузы) |
| `care_shown` | Что показано |
| `care_reaction` | Реакция тренера |

**Стоимость сейчас:** 4 поля в существующих таблицах.
**Без этого потом:** не будет данных для калибровки.

### 4. Настройка потолка поддержки

Не UI для температуры, а **простой переключатель**: «Уровень поддержки: низкий / средний / высокий».

**Стоимость сейчас:** один переключатель.
**Без этого потом:** миграция настроек.

### 5. Точка расширения в коде

Не реализация, а **место**, куда поддержка будет встроена. Например, функция `get_care_temperature(trainer_id)`, которая пока возвращает 0 или 1.

**Стоимость сейчас:** одна функция-заглушка.
**Без этого потом:** встраивание в несколько мест.

## Что НЕ закладывается в MVP

| Не делаем | Почему |
|---|---|
| Формулу температуры | Нет данных для калибровки |
| Оценку состояния | Нет сигналов, нет истории |
| Автоматическую корректировку | Нечего корректировать |
| Уровни 2–4 | Риск «зловещей долины» на старте |
| UI для температуры | Избыточно |
| Логику «предложить паузу» | Преждевременно |

**Принцип:** в MVP поддержка — это **только факты** (уровень 0–1). Всё остальное — после MVP.

## Где в волнах

| Волна | Что делаем с поддержкой |
|---|---|
| **1. Пилот** | Ничего |
| **2. Архитектура** | Поддержка описана как сквозной параметр |
| **3. Согласование** | Проверяем, есть ли данные для сигналов состояния |
| **4. Стратегический слой** | Параметры профиля в анкете |
| **5. Операционный + инструментальный + образовательный** | Видимый прогресс в брифе; поля в логировании; настройка потолка; точка расширения |
| **6. Конкретика** | Формула температуры, правила уровней |
| **7. Разработка** | Реализация поддержки (отдельный этап после MVP) |

## Как проверить, что фундамент достаточен

Перед реализацией поддержки (после MVP):

| Вопрос | Если «нет» |
|---|---|
| Есть ли в анкете параметры для калибровки? | Добавить |
| Есть ли видимый прогресс в брифе? | Добавить |
| Логируются ли сигналы состояния? | Добавить |
| Есть ли потолок поддержки? | Добавить |
| Есть ли точка расширения в коде? | Добавить |
| Есть ли данные за 2–4 недели? | Подождать |

## Почему «поддержка», а не «забота»

| Забота | Поддержка |
|---|---|
| От ИИ звучит фальшиво | Нейтрально |
| Подразумевает эмоции | Подразумевает помощь |
| Требует эмпатии | Требует внимания |
| Легко скатиться в манипуляцию | Сложнее |
| «Я тебя понимаю» | «Вот что работает» |

**Поддержка** — это помощь в действии, а не воздействие на состояние. Ближе к «я рядом», чем к «я тебя люблю».

---

## Риски и как их избегать

| Риск | Как избегать |
|---|---|
| Ошибка в оценке состояния | Не делать выводов по одному сигналу; спрашивать |
| Слишком высокая температура | Потолок задаёт тренер; при сомнении — понижать |
| Манипуляция | Цель — помочь, а не удержать |
| Неискренность | Поддержка обоснована фактами |
| «Зловещая долина» | Начинать с низкой температуры |

## Итог

| Аспект | Решение |
|---|---|
| **Что это** | Сквозной параметр поддержки |
| **Уровни** | 0–4, калибруются под профиль и состояние |
| **Кто управляет** | Код, не ИИ |
| **Контроль** | Потолок задаёт тренер |
| **Роль ИИ** | Формулировка, не решение |
| **В MVP** | Только фундамент |
| **После MVP** | Реализация |
| **Ключевой принцип** | Поддержка, не мотивация |

**Главная идея:** поддержка — это **не функция MVP**, а **этап развития**. Но фундамент для неё закладывается в MVP, потому что без него потом придётся переделывать анкету, бриф, логирование и код. В MVP — только факты (уровень 0–1). Всё остальное — когда появятся данные и понимание, как тренеры реагируют.
