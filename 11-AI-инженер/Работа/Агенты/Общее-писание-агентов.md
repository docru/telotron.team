# Общее описание модуля с учётом оркестратора

## Что это

**ИИ-консультант продаж** — встроенный помощник в разделе Pro «Поиск клиентов», который помогает фитнес-тренеру системно привлекать клиентов. Система работает как **цифровой РОП + наставник**: диагностирует ситуацию, предлагает стратегию, ставит ежедневные задачи, даёт инструменты и попутно обучает основам маркетинга и продаж.

**Ключевая философия:** код решает, ИИ объясняет и адаптирует, тренер действует, оркестратор координирует.

**Что система НЕ делает:**
- Не работает с лидами напрямую (пилот)
- Не даёт медицинских, юридических, финансовых советов
- Не обещает конкретных результатов
- Не давит на лидов
- Не заставляет учиться — только предлагает

## 1. Оркестратор

**Что это:** центральный управляющий компонент. Не ИИ — детерминированный код. Решает, **какой агент, когда, с каким контекстом и в какой последовательности запускать**, и **что делать при сбоях**.

**Метафора:** дирижёр. Не играет сам, но без него оркестр превращается в какофонию.

### Функции

**1. Триггеры запуска**

| Цикл | Триггеры |
|---|---|
| Стратегический | Календарь (2–4 недели), провал метрик, смена предложения, ручной запрос, накопление задач |
| Операционный | Ежедневно в 07:00, новые данные, ручной запрос |
| Инструментальный | Открытие задачи, редактирование, запрос тренера |

**2. Последовательность вызовов**

Оркестратор знает граф вызовов и не позволяет нарушать порядок:

- Стратегический цикл: сбор контекста → Диагност → [проверка] → Стратег → [выбор тренера] → Декомпозер → задачи
- Операционный цикл: сбор → нормализация → скоринг → отсечение → Исполнитель → валидация → бриф
- Дельта-режим: событие → проверка → вызов → добавление дельты

**3. Управление контекстом**

Каждый агент получает только то, что нужно для его задачи. Диагност не получает RAG-методики. Исполнитель не получает всю историю стратегий. Меньше контекста — меньше шума, ниже стоимость, выше точность.

**4. Обработка сбоев**

| Сбой | Действие |
|---|---|
| Диагност | Уведомить, не запускать Стратега |
| Стратег | Повторить 1 раз, затем fallback |
| Декомпозер | Задачи не создаются, fallback на шаблоны |
| Исполнитель | Бриф по правилам с пометкой «без ИИ» |
| Инструмент | Шаблонный вариант |
| Провайдер | Fallback на правила |
| Валидация | Отбраковка, fallback, логирование |

**Принцип:** тренер никогда не остаётся без результата.

**5. Лимиты и бюджет**

- 6 вызовов ИИ на тренера в сутки
- ≤ 0,22 ₽/сутки
- При исчерпании — режим «без ИИ» до следующего дня
- Каждый вызов логируется

**6. Управление состоянием**

Оркестратор знает: активную стратегию, зафиксированный бриф, выполненные задачи, изменения данных, использованные лимиты.

**7. Приоритизация конфликтов**

- «Горячий» лид из CRM vs стратегия → CRM
- Стратегия с дедлайном vs рутина → стратегия
- Две задачи на одного лида → объединить
- Задача требует навыка, которого нет → понизить или добавить обучающий шаг

**Конфликты решает код, не ИИ.**

### Чего оркестратор НЕ делает

| Не делает | Кто делает |
|---|---|
| Содержательные решения | Стратег, тренер |
| Генерацию текста | Исполнитель |
| Обучение | Слой обучения |
| Валидацию | Валидатор |
| Работу с данными | Модули сбора |
| Промпты | Промпт-менеджер |

## 2. Стратегический слой

**Задача:** раз в 2–4 недели (или по триггеру) пересмотреть картину, предложить направление, разбить на задачи.

### Агенты

| Агент | Роль | Вход | Выход |
|---|---|---|---|
| **Диагност** | Анализ ситуации | Профиль, метрики, история, текущая стратегия | Диагноз: что работает, что нет, гипотезы |
| **Стратег** | Генерация 2–3 стратегий | Диагноз, профиль, RAG, few-shot | Стратегии + рекомендация |
| **Декомпозер** | Разбивка на задачи | Выбранная стратегия, ресурсы, шаблоны | Задачи, вехи, критерии успеха |
| **Монитор** | Оценка прогресса | Метрики, критерии | Статус + рекомендация |

### Цикл

```
Триггер → Диагност → Стратег → [выбор тренера] → Декомпозер → задачи
                                        ↓
                              Монитор (периодически)
```

### Роль ИИ: высокая

Интерпретация, генерация, обоснование, декомпозиция.

### Влияние образовательного слоя

- Диагност оценивает компетенции
- Стратег учитывает зону ближайшего развития
- Декомпозер добавляет обучающие шаги

## 3. Операционный слой

**Задача:** ежедневно в 07:00 выдать 1–3 задачи с «зачем».

### Принцип: код решает, ИИ объясняет

**Код:** сбор, нормализация, скоринг, отсечение, валидация, сборка, фиксация.

**ИИ:** финальный выбор 1–3 из топ-N + генерация «зачем».

### Скоринг

Многофакторная модель:
- Просрочка (10/день)
- Тип задачи (заявка 30, договорённость 25, напоминание 15, реактивация 10, контент 5)
- Стадия лида (горячий 20, тёплый 10, холодный 5)
- Давность касания (2/день)
- Источник (стратегия +15)
- Образовательный фактор (±)

Формула: сумма произведений факторов на веса.

### Цикл

```
07:00 → Сбор → Нормализация → Скоринг → Отсечение
     → ИИ → Валидация → Бриф → Тренер → Обратная связь
```

### Fallback

При любом нарушении — бриф по правилам с пометкой «без ИИ».

### Влияние образовательного слоя

Бриф содержит микро-обучающие элементы. Скоринг учитывает образовательный фактор. Исполнитель добавляет «как» к «зачем».

## 4. Инструментальный слой

**Задача:** автоматизировать рутину по событию.

### Классификация

**Скриптовые (без ИИ):** подстановка шаблона, выгрузка, напоминание, трекинг, обновление статуса.

**ИИ-инструменты:** черновик сообщения, переформулировка поста, анализ ответа, резюме, генерация «зачем».

### Принцип

Инструмент предлагается **только если релевантен текущей задаче и стратегии**.

### Роль ИИ: точечная

### Влияние образовательного слоя

Два режима: «Сделай за меня» / «Покажи, как». Режим выбирается по карте компетенций.

Новый инструмент «Разбор»: анализ правок тренера.

---

## 5. Образовательный слой (сквозной)

**Задача:** повысить компетентность тренера до уровня, необходимого для эффективного сотрудничества.

### Принципы

1. Обучение встроено в действие
2. Только то, что нужно сейчас
3. Без терминов
4. Проверка через действие
5. Не блокирует — предлагает

### Карта компетенций

| Навык | Уровень | Как определён |
|---|---|---|
| Первое касание | Освоен | 10 задач без правок |
| Реактивация | В процессе | 3 задачи, 2 с правками |
| Возражения | Не начат | Нет задач |

**Обновляется:** автоматически по логам, вручную тренером, через разбор.

### Форматы микро-обучения

| Тип | Когда | Пример |
|---|---|---|
| Пример | Впервые | «Вот как другие писали» |
| Принцип | Повторяет ошибку | «Короткие сообщения получают больше ответов» |
| Чек-лист | Сложная задача | «Имя, повод, вопрос, без давления» |
| Разбор | Отредактировал | «Ты убрал призыв — вот почему это важно» |

### Роль ИИ: низкая

Выбор из подготовленных шаблонов + адаптация под стиль.

---

## 6. Логирование и обучение

**Задача:** собирать данные для отладки, аудита и обучения.

### Принципы

1. Часть архитектуры, не «потом»
2. Структурированные логи
3. PII-минимизация
4. Три горизонта: тексты (30 дней), метаданные (1 год), агрегаты (постоянно)

### Что логируется

| Таблица | Что | Срок |
|---|---|---|
| `ai_runs` | Каждый вызов ИИ | Тексты 30 дн, метаданные 1 год |
| `strategy_runs` | Стратегический цикл | 1 год |
| `tool_runs` | Вызовы инструментов | 1 год |
| `metrics_daily` | Агрегаты за день | 1 год |
| `micro_learning` | Образовательные сигналы | 1 год |

### Обработка

**Агрегация (ежедневно):** по тренеру, агенту, инструменту, стратегии.

**Оценка качества:** доля валидных, fallback, принятых инструментов, достижение критериев.

**Обучение:**

| Уровень | Что берём | Как используем |
|---|---|---|
| Веса скоринга | Выполнено/отложено/отклонено | Корректировка весов |
| Few-shot | Стратегии + результат | Добавление в промпт |
| RAG | Инструменты + принятие | Обновление методик |
| Карта компетенций | Образовательные сигналы | Обновление уровней |

**Аудит:** проверка на запрещённые формулировки, injection, утечки PII, аномалии.

### Роль ИИ: нет

---

## 7. Адаптация под тренера (сквозной механизм)

**Задача:** превратить общего агента в персонального помощника.

### Что адаптируется

- **Профиль:** предложение, аудитория, опыт, ресурсы, цели
- **Стиль:** тон, длина, эмодзи, обращения
- **История:** выполненные, отклонённые, отредактированные
- **Контекст:** стратегия, метрики, сезонность
- **Компетенции:** карта навыков, скорость обучения

### Уровни

| Уровень | Что | Как | Когда |
|---|---|---|---|
| Контекст | Профиль, стиль | Подстановка в промпт | С первого дня |
| Примеры | Формулировки | Few-shot | Через 1–2 недели |
| Веса | Приоритеты | Корректировка скоринга | Через 2–4 недели |
| Компетенции | Сложность | Карта навыков | Через 2–4 недели |

### Холодный старт

Анкета → онбординг (3–5 вопросов) → ручная валидация первых 10–20 брифов.

## 9. Принципы

1. **Оркестратор координирует, код решает, ИИ объясняет.**
2. **Каждый выход модели проверяем.**
3. **Обратная связь — first-class.**
4. **Идемпотентность.** Бриф фиксируется, изменения — дельтой.
5. **Governance встроен, а не декларирован.**
6. **RAG вместо fine-tuning.**
7. **Скоринг вместо интуиции.**
8. **Обучение — инженерия знаний, не ML.**
9. **Микро-обучение не блокирует.**
10. **Адаптация меняет форму, но не границы.**
11. **Тренер не остаётся без результата при сбое.**

## Итог

| Компонент | Роль ИИ | Ключевое |
|---|---|---|
| **Оркестратор** | Нет | Координация, сбои, лимиты, состояние |
| **Стратегический** | Высокая | Диагност, Стратег, Декомпозер, Монитор |
| **Операционный** | Умеренная | Скоринг, Исполнитель, Валидация |
| **Инструментальный** | Точечная | Черновики, анализ, разбор |
| **Образовательный** | Низкая | Карта компетенций, микро-обучение |
| **Логирование** | Нет | ai_runs, metrics_daily, обучение |
| **Адаптация** | Сквозная | Профиль, стиль, история, компетенции |

**Главная идея:** система — это **цифровой РОП + наставник**, управляемый оркестратором. Оркестратор гарантирует, что каждый агент вызывается вовремя, с нужным контекстом, в рамках лимитов и с fallback при сбое. Тренер получает не только помощь, но и рост компетентности — что делает сотрудничество долгосрочным и эффективным.
