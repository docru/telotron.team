# Скоринг: полное описание

## 1. Назначение

**Скоринг** — это числовая оценка приоритета объекта по набору факторов. В вашей системе он решает, **какие задачи попадут в топ для передачи в ИИ** и **какие методики из RAG будут использованы**.

**Задача:** из 15+ открытых задач выбрать 8–10 наиболее важных, чтобы ИИ работал с чистым, отсортированным входом. И из десятков методик выбрать 5 наиболее релевантных.

**Ритм:** ежедневно (операционный слой) и периодически (стратегический слой).

**Роль ИИ:** нет. Скоринг — это детерминированный код.

---

## 2. Место в архитектуре

```
┌─────────────────────────────────────────────────────────────┐
│                      ОРКЕСТРАТОР                            │
│  Запускает скоринг перед вызовом ИИ                         │
└─────────────────────────────────────────────────────────────┘
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
┌───────────────┐   ┌─────────────────┐   ┌─────────────────┐
│ СТРАТЕГИЧЕСКИЙ│   │ ОПЕРАЦИОННЫЙ    │   │ ИНСТРУМЕНТАЛЬНЫЙ│
│ СЛОЙ          │   │ СЛОЙ            │   │ СЛОЙ            │
│ Скоринг       │   │ Скоринг         │   │ Не используется │
│ релевантности │   │ важности задач  │   │                 │
│ методик       │   │                 │   │                 │
└───────────────┘   └─────────────────┘   └─────────────────┘
```

**Где применяется:**
- **Операционный слой:** сортировка задач для брифа.
- **Стратегический слой:** ранжирование методик из RAG, рекомендация стратегий.
- **Образовательный слой:** приоритизация подсказок.

## 3. Принципы

**1. Детерминированность.**
Код считает одинаково каждый раз. ИИ не участвует в скоринге.

**2. Объяснимость.**
Для каждой задачи можно сказать, почему у неё такой скор. Это важно для доверия тренера.

**3. Настраиваемость.**
Веса — это гипотеза, которая корректируется по обратной связи.

**4. PII-безопасность.**
Скоринг работает с метаданными (тип, дата, стадия), не с текстом переписки.

**5. Экономия.**
Не надо гонять модель на то, что решается арифметикой.

## 4. Скоринг в операционном слое

### 4.1. Факторы

Скоринг строится на **многофакторной модели**. Каждый фактор имеет вес.

**Обязательные факторы (ядро):**

| Фактор | Что измеряет | Логика |
|---|---|---|
| **Просрочка** | Дней с момента дедлайна | Чем больше просрочка, тем выше приоритет |
| **Тип задачи** | Ответ на заявку > Договорённость > Напоминание > Реактивация > Контент | Ответ на заявку — максимальный приоритет |
| **Стадия лида** | Горячий / Тёплый / Холодный | Горячий лид требует немедленного внимания |
| **Давность касания** | Дней без контакта | Чем дольше молчание, тем выше риск потери |

**Контекстные факторы (опциональные):**

| Фактор | Что измеряет | Логика |
|---|---|---|
| **Источник задачи** | CRM / Стратегия / Календарь | Задачи из стратегии получают бонус |
| **Ресурсы тренера** | Соответствие задачи возможностям | Если задача требует того, что тренер не готов делать — штраф |
| **Историческое выполнение** | Как часто тренер выполняет задачи такого типа | Если тип систематически отклоняется — понижение |
| **Образовательный фактор** | Требует ли задача нового навыка | Если требует — понижение или повышение |
| **Время суток / день недели** | Контекст выполнения | Некоторые задачи лучше утром |

### 4.2. Формула

```
score = сумма (фактор × вес)
```

### 4.3. Пример расчёта

**Задача 1: Ответ на заявку от горячего лида, просрочка 3 дня**

| Фактор | Значение | Вес | Вклад |
|---|---|---|---|
| Просрочка | 3 дня | 10/день | 30 |
| Тип задачи | Ответ на заявку | 30 | 30 |
| Стадия лида | Горячий | 20 | 20 |
| Давность касания | 5 дней | 2/день | 10 |
| Источник | CRM | 0 | 0 |
| **Итого** | | | **90** |

**Задача 2: Напоминание тёплому лиду из стратегии**

| Фактор | Значение | Вес | Вклад |
|---|---|---|---|
| Просрочка | 0 | 10/день | 0 |
| Тип задачи | Напоминание | 15 | 15 |
| Стадия лида | Тёплый | 10 | 10 |
| Давность касания | 10 дней | 2/день | 20 |
| Источник | Стратегия | +15 | 15 |
| **Итого** | | | **60** |

**Результат:** первая задача (90) идёт в топ, вторая (60) — в середину.

### 4.4. Пороги отсечения

| Порог | Действие |
|---|---|
| score < 20 | Не включать в бриф (если есть задачи с более высоким скором) |
| score < 10 | Не включать никогда (кроме случаев, когда других задач нет) |

**Важно:** отсечение — это не «удаление», а «откладывание». Задача остаётся в CRM и может вернуться в бриф позже, когда её скор вырастет.

### 4.5. Топ-N для ИИ

После скоринга код оставляет **топ-8–10** задач для передачи в ИИ. Это:
- Снижает нагрузку на модель
- Уменьшает стоимость
- Повышает точность (ИИ выбирает из «хороших», а не из «всех»)

## 5. Скоринг в стратегическом слое

Скоринг применяется не только в операционном слое, но и в стратегическом — для **релевантности методик из RAG**.

### 5.1. Скоринг релевантности методик

Когда Стратег запрашивает методики из RAG, система возвращает не просто «топ-5 по векторной близости», а **переранжирует их по скорингу**.

| Фактор | Что измеряет | Логика |
|---|---|---|
| **Семантическая близость** | Насколько методика соответствует запросу | Базовый скор |
| **Применимость к профилю** | Подходит ли для этого тренера | Размер базы, ресурсы, аудитория |
| **Историческая успешность** | Как часто срабатывала в похожих ситуациях | Бонус за успех |
| **Свежесть** | Не устарела ли методика | Штраф за устаревание |
| **Соответствие компетенциям** | Может ли тренер её реализовать | Штраф, если требует новых навыков |

**Формула:** аналогичная — сумма произведений.

### 5.2. Скоринг стратегий

Когда Стратег генерирует 2–3 стратегии, код может **переранжировать их** по скорингу перед показом тренеру.

| Фактор | Что измеряет |
|---|---|
| **Соответствие ресурсам** | Может ли тренер реализовать |
| **Ожидаемый эффект** | Насколько решает проблему из диагноза |
| **Риск** | Насколько рискованна |
| **Простота** | Насколько легко начать |

**Но:** финальный выбор — за тренером. Скоринг только рекомендует.

## 6. Скоринг в образовательном слое

### 6.1. Приоритизация подсказок

Когда есть несколько микро-обучающих элементов, скоринг решает, **какой показать**.

| Фактор | Что измеряет |
|---|---|
| **Релевантность задаче** | Насколько подсказка связана с текущей задачей |
| **Актуальность пробела** | Насколько навык важен для текущей стратегии |
| **Свежесть** | Показывали ли это недавно |
| **Предпочтения тренера** | Какой формат он предпочитает |

## 7. Веса: откуда берутся и как меняются

### 7.1. Экспертные веса на старте

Пока нет данных — веса задаются экспертно. Это **гипотеза**, а не истина.

**Пример стартовых весов:**

| Фактор | Вес | Обоснование |
|---|---|---|
| Просрочка | 10/день | Просроченные договорённости — главный источник потери доверия |
| Ответ на заявку | 30 | Новая заявка — самый горячий сигнал |
| Договорённость | 25 | Обязательство перед лидом |
| Напоминание | 15 | Важно, но не срочно |
| Реактивация | 10 | Долгая игра |
| Контент | 5 | Регулярно, но не срочно |
| Горячий лид | 20 | Высокая вероятность конверсии |
| Тёплый лид | 10 | Средняя вероятность |
| Холодный лид | 5 | Низкая вероятность |
| Давность касания | 2/день | Риск потери растёт со временем |

### 7.2. Корректировка по обратной связи

**Сигналы от тренера:**

| Действие | Сигнал | Что меняется |
|---|---|---|
| Выполнено | +1 | Вес типа задачи растёт |
| Отложено | 0 | Без изменений |
| Отклонено | −1 | Вес типа задачи падает |
| «Не показывать такое» | −2 | Вес фактора резко падает |

**Формула корректировки:**

```
новый_вес = старый_вес × (1 + α × сигнал)
```

Где α — скорость обучения (например, 0.1).

**Пример:** если задачи типа «Напоминание» отклоняются в 80% случаев, вес падает с 15 до ~3. Через месяц такие задачи почти не попадают в топ.

### 7.3. Версионирование весов

Каждый набор весов имеет версию. В логах пишется:
- `weights_version`
- `factors` (JSON с значениями)
- `final_score`
- `rank`

Это позволяет:
- Разобрать инцидент («почему эта задача не попала в бриф»)
- Проанализировать, какие факторы чаще всего влияют на топ
- Откатить веса, если качество упало

## 8. Логирование скоринга

Каждый расчёт скоринга логируется.

| Поле | Назначение |
|---|---|
| `task_id` | Идентификатор задачи |
| `timestamp` | Время расчёта |
| `factors` | JSON с факторами и значениями |
| `weights_version` | Версия весов |
| `final_score` | Итоговый скор |
| `rank` | Место в рейтинге |
| `included_in_brief` | Попала ли в бриф |

**Зачем:**
- Разобрать инцидент
- Проанализировать, какие факторы чаще всего влияют на топ
- Откатить веса, если качество упало

## 9. Связь с другими компонентами

```
ОПЕРАЦИОННЫЙ СЛОЙ
  Сбор задач → Скоринг → Отсечение → Топ-N → ИИ
                    │
                    ▼
              Логирование
                    │
                    ▼
              ОБРАТНАЯ СВЯЗЬ
              (выполнено/отложено/отклонено)
                    │
                    ▼
              КОРРЕКТИРОВКА ВЕСОВ
                    │
                    ▼
              Следующий цикл точнее
```

**Стратегический слой** использует скоринг для:
- Ранжирования методик из RAG
- Рекомендации стратегий

**Образовательный слой** использует скоринг для:
- Приоритизации подсказок

**Логирование** фиксирует:
- Факторы и веса
- Итоговый скор
- Результат

## 10. Метрики скоринга

| Метрика | Что показывает |
|---|---|
| Доля выполненных задач из топа | Точность скоринга |
| Доля отклонённых из топа | Релевантность |
| Корреляция скора и выполнения | Насколько скор предсказывает действие |
| Стабильность весов | Насколько часто меняются |
| Время расчёта | Производительность |

---

## 11. Governance

### 11.1. Ограничения

- Скоринг не может «выбросить» задачу навсегда — только отложить
- Скоринг не может противоречить ограничениям (медицина, обещания)
- Веса не могут уйти в отрицательные значения
- Максимальный вес фактора ограничен

### 11.2. Аудит

- Все расчёты логируются
- Версии весов сохраняются
- Тренер может посмотреть, почему задача в топе

---

## 12. Что это значит для реализации

### Минимальный MVP

1. 4–5 обязательных факторов (просрочка, тип, стадия, давность)
2. Экспертные веса
3. Формула `score = сумма (фактор × вес)`
4. Порог отсечения (20)
5. Топ-N для ИИ (8–10)
6. Логирование расчётов

### Что можно отложить

- Контекстные факторы (ресурсы, время суток)
- Автоматическую корректировку весов
- Скоринг релевантности методик
- Скоринг подсказок

### Что нельзя откладывать

- Логирование `factors` и `final_score`
- `weights_version`
- Возможность ручной корректировки весов
- Порог отсечения
- Топ-N для ИИ

---

## 13. Принципы

1. **Скоринг — детерминированный код, не ИИ.**
2. **Веса — гипотеза, а не истина.**
3. **Объяснимость обязательна.**
4. **Отсечение — это откладывание, не удаление.**
5. **Логирование — обязательно.**
6. **Корректировка — по обратной связи.**

## Итог

| Аспект | Решение |
|---|---|
| **Назначение** | Числовая оценка приоритета |
| **Ритм** | Ежедневно + периодически |
| **Роль ИИ** | Нет |
| **Факторы** | Просрочка, тип, стадия, давность + контекстные |
| **Формула** | `score = сумма (фактор × вес)` |
| **Веса** | Экспертные на старте, корректируются по обратной связи |
| **Отсечение** | Порог 20 |
| **Топ-N** | 8–10 для ИИ |
| **Логирование** | factors, weights_version, final_score |
| **Обучение** | `новый_вес = старый × (1 + α × сигнал)` |

**Главная идея:** скоринг — это **инфраструктура для ИИ**. Он не заменяет модель, а готовит для неё чистый, отсортированный вход. Без качественного скоринга ИИ будет выбирать «не то», и вся система потеряет смысл.
