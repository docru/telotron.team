# Адаптация: полное описание

## 1. Назначение

**Адаптация** — это сквозной механизм, который превращает **общего агента для продаж** в **персонального помощника конкретного тренера**. Без неё система даёт одинаковые советы всем, а тренеры разные: у одного база 200 человек и Instagram, у другого — 30 лидов в WhatsApp и ноль контента.

**Задача:** настроить поведение всех агентов под профиль, стиль, историю и компетенции конкретного тренера — так, чтобы система говорила его словами, предлагала реалистичные задачи и училась на его реакциях.

**Ритм:** постоянный. Адаптация работает с первого дня и углубляется со временем.

**Роль ИИ:** сквозная. ИИ используется и для подстановки контекста, и для генерации few-shot примеров, и для анализа истории.

## 3. Что адаптируется

Адаптация идёт по **пяти осям**, каждая из которых влияет на разных агентов.

### 3.1. Профиль (кто он)

Базовый слой. Определяет, какие стратегии вообще применимы.

| Параметр | Влияет на |
|---|---|
| **Предложение** (услуги, цены, USP) | Стратег: какие методики релевантны |
| **Аудитория** (кто клиенты) | Инструменты: тон, темы, каналы |
| **Опыт продаж** | Стратег: сложность стратегий |
| **Опыт маркетинга** | Декомпозер: тип задач |
| **Ресурсы** (часы, бюджет, готовность) | Декомпозер: реалистичность задач |
| **Цели** (больше клиентов / выше чек / новая ниша) | Стратег: критерии успеха |

### 3.2. Стиль (как он говорит)

Определяет, **как** агенты формулируют текст.

| Параметр | Пример | Влияет на |
|---|---|---|
| **Тон** | Дружелюбный / формальный / без давления | Исполнитель: «зачем» |
| **Длина сообщений** | Короткие / развёрнутые | Инструменты: черновики |
| **Эмодзи** | Да / нет / умеренно | Инструменты: черновики |
| **Обращения** | «Ты» / «Вы» | Все тексты |
| **Запрещённые слова** | «Клиент» вместо «пациент» | Валидация |

### 3.3. История (что он делал)

Определяет, **что** система предлагает.

| Сигнал | Что показывает | Влияет на |
|---|---|---|
| Выполненные задачи | Что тренер реально делает | Скоринг: веса |
| Отклонённые задачи | Что он не будет делать | Скоринг + Декомпозер |
| Отредактированные тексты | Как он меняет черновики | Few-shot примеры |
| Результаты стратегий | Что сработало | RAG: кейсы |

### 3.4. Компетенции (что умеет)

Определяет, **насколько сложные** задачи предлагать и **как** учить.

| Параметр | Влияет на |
|---|---|
| Карта навыков | Режим работы инструментов |
| Скорость обучения | Частота микро-обучения |
| Предпочтения | Формат подсказок |

### 3.5. Контекст (где он сейчас)

Определяет, **когда** и **что** предлагать.

| Параметр | Влияет на |
|---|---|
| Текущая стратегия | Исполнитель: источник задач |
| Метрики воронки | Диагност: узкие места |
| Сезонность | Исполнитель: приоритеты |
| Загруженность | Скоринг: реалистичность |

## 4. Уровни адаптации

Адаптация происходит на **четырёх уровнях**, от простого к сложному.

### 4.1. Уровень 1: Контекст (промпт)

**Самый простой и быстрый.** Профиль и стиль тренера подкладываются в промпт каждого агента.

**Пример для Исполнителя:**
```
Ты — помощник фитнес-тренера.

ПРОФИЛЬ ТРЕНЕРА:
- Предложение: персональные тренировки, 5000-15000 ₽
- Аудитория: женщины 30-45, восстановление после родов
- Стиль: дружелюбный, без давления, короткие сообщения
- Обращение: «Вы»
- Эмодзи: умеренно

ЗАДАЧА:
Выбери 1-3 задачи и напиши «зачем» в этом стиле.
```

**Что даёт:**
- Тексты звучат «как тренер»
- Задачи соответствуют ресурсам
- Не требует обучения

**Ограничение:** не адаптируется со временем. Что задали — то и работает.

### 4.2. Уровень 2: Примеры (few-shot)

**Средний уровень.** В промпт добавляются примеры из прошлого опыта — как этот тренер писал, что выполнял, что отклонял.

**Пример для инструмента «Черновик сообщения»:**
```
ПРИМЕРЫ СООБЩЕНИЙ ЭТОГО ТРЕНЕРА:

Пример 1 (принято):
"Привет, Анна! Как ваши тренировки? Хотела напомнить, 
что в пятницу есть свободное время. 😊"

Пример 2 (отредактировано тренером):
Было: "Уважаемая Анна, напоминаю о записи."
Стало: "Анна, привет! Напоминаю о пятнице — всё в силе?"

Пример 3 (отклонено):
"Уважаемая Анна! Напоминаем, что запись на тренировку 
обязательна."
Причина: слишком формально.

ЗАДАЧА:
Напиши черновик в этом стиле.
```

**Что даёт:**
- Система учится на реальном поведении
- Стиль уточняется со временем
- Не требует переобучения модели

**Технически:**
- Храните `(задача, черновик, действие_тренера)` в БД
- При вызове инструмента доставайте 3–5 релевантных примеров
- Подкладывайте в промпт

### 4.3. Уровень 3: Веса (скоринг)

**Самый глубокий уровень.** Система меняет **что** предлагать, а не только **как**.

**Пример:**
- Тренер систематически отклоняет задачи типа «написать пост» → вес падает
- Тренер выполняет задачи типа «позвонить» → вес растёт
- Тренер игнорирует лидов с холодной стадией → вес стадии падает

**Технически:**
- Логируйте `(тип_задачи, действие_тренера)`
- Раз в неделю агрегируйте
- Корректируйте веса: `новый_вес = старый × (1 + α × сигнал)`
- Версионируйте веса

**Что даёт:**
- Система перестаёт предлагать то, что тренер не делает
- Приоритеты смещаются под реальное поведение
- Не требует ML

### 4.4. Уровень 4: Компетенции (карта навыков)

**Образовательный уровень.** Система меняет **сложность** задач и **режим** инструментов.

**Пример:**
- Навык «первое касание» освоен → инструмент работает в режиме «Сделай за меня»
- Навык «реактивация» в процессе → инструмент работает в режиме «Покажи, как»
- Навык «возражения» не начат → система не предлагает задачи, требующие этого навыка

**Технически:**
- Карта компетенций обновляется по логам
- Режим инструмента выбирается по карте
- Сложность задач растёт по мере освоения

**Что даёт:**
- Система не перегружает тренера
- Обучение встроено в действие
- Прогресс виден

## 5. Что адаптируется у каждого агента

| Агент | Что адаптируется | Как |
|---|---|---|
| **Диагност** | Какие метрики считать «узкими местами» | Профиль + история |
| **Стратег** | Какие стратегии предлагать | Профиль + ресурсы + RAG + few-shot |
| **Декомпозер** | Какие задачи генерировать | Ресурсы + история + компетенции |
| **Монитор** | Какие критерии считать успехом | Цели тренера |
| **Исполнитель** | Какие задачи выбирать + как писать «зачем» | Профиль + стиль + скоринг |
| **Инструменты** | Как писать черновики + режим работы | Стиль + few-shot + компетенции |

## 7. Холодный старт: как адаптировать без данных

Проблема: у нового тренера нет истории. Что делать?

**Решение — трёхшаговая стратегия:**

### Шаг 1. Анкета (обязательно)

Тренер заполняет профиль: предложение, аудитория, стиль, ресурсы, цели. Этого достаточно для базовой адаптации через промпт.

**Что спрашиваем:**
- Что ты продаёшь и кому?
- Сколько лет в профессии?
- Какой у тебя опыт продаж?
- Сколько времени готов тратить на продвижение?
- Что готов делать, а что — нет?
- Как ты обычно общаешься с клиентами?
- Какие цели на ближайшие 3 месяца?

### Шаг 2. Быстрый онбординг (первые 3 дня)

Система задаёт 3–5 уточняющих вопросов:
- «Покажи пример сообщения, которое тебе нравится»
- «Что ты точно не будешь делать?»
- «Сколько времени в день готов тратить?»

Это даёт первые few-shot примеры и калибрует веса.

### Шаг 3. Ручная валидация (первые 2 недели)

Первые 10–20 брифов вы (или куратор) проверяете вручную. Корректируете промпты и веса. Это дорого, но необходимо, пока нет данных.

## 8. Governance адаптации

Адаптация не должна ломать ограничения.

### 8.1. Что нельзя адаптировать

- Запрет на медицину, питание, юристов
- Запрет на обещания конкретных результатов
- Запрет на давление
- PII-минимизация

### 8.2. Что можно адаптировать

- Тон, стиль, длина
- Приоритеты задач
- Выбор стратегий
- Формулировки
- Режим инструментов
- Сложность задач

**Правило:** адаптация меняет **форму**, но не **границы**.

### 8.3. Аудит

- Версионируйте веса и промпты
- Логируйте, какие примеры подкладывались
- Если тренер пожалуется — есть трассировка

## 11. Метрики адаптации

| Метрика | Что показывает |
|---|---|
| Доля выполненных задач | Насколько бриф релевантен |
| Доля отклонённых | Насколько система «попала» |
| Доля принятых черновиков | Насколько стиль точен |
| Доля отредактированных | Насколько стиль близок |
| Скорость освоения навыков | Насколько эффективно обучение |
| Конверсия до/после адаптации | Влияние на бизнес |

## 12. Что это значит для реализации

### Минимальный MVP

1. Анкета тренера (профиль + стиль)
2. Подстановка профиля в промпты всех агентов
3. Логирование действий тренера
4. Ручная корректировка весов раз в неделю

### Что можно отложить

- Автоматическую корректировку весов
- Few-shot примеры (если нет данных)
- Карту компетенций
- Адаптацию через RAG-кейсы

### Что нельзя откладывать

- Анкету (без неё нет адаптации)
- Логирование действий
- Версионирование весов и промптов
- Governance-границы

---

## 13. Принципы

1. **Адаптация — это инженерия контекста, а не переобучение модели.**
2. **Модель остаётся той же. Меняется то, что вы ей даёте на вход.**
3. **Адаптация меняет форму, но не границы.**
4. **Без обратной связи адаптация невозможна.**
5. **Холодный старт — через анкету и ручную валидацию.**
6. **Версионирование — обязательно.**

## Итог

| Аспект | Решение |
|---|---|
| **Назначение** | Превратить общего агента в персонального |
| **Ритм** | Постоянный |
| **Роль ИИ** | Сквозная |
| **Оси** | Профиль, стиль, история, компетенции, контекст |
| **Уровни** | Контекст → Примеры → Веса → Компетенции |
| **Холодный старт** | Анкета → онбординг → ручная валидация |
| **Ключевой принцип** | Инженерия контекста, не переобучение |
| **Governance** | Меняет форму, но не границы |

**Главная идея:** адаптация — это **не переобучение модели**, а **инженерия контекста**. Модель остаётся той же. Меняется то, что вы ей даёте на вход, и то, как вы интерпретируете выход. Это дёшево, объяснимо и работает без больших данных.
