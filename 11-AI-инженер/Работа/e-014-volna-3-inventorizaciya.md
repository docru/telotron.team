## 1) Что уже есть

### CRM (E-006)

- HTTP Pro: контакты, статус, заметки (`author_type`: trainer|ai|system), next_action, invite.
- Домен: `CrmContactService` — канон для всех потребителей (E-008/E-010 не бьют в браузерный CRM API).
- События: `CrmContactCreated`, `StatusChanged`, `NoteAdded`, `NextActionChanged` → подписчик LeadGen.
- Чтение для брифа: `CrmLeadGenReadService` (только read; воронка 7д с `trials: null`).
- **ИИ в CRM не пишет** (продуктово ADR-011), хотя HTTP `author_type=ai` допускает.

### LeadGen (E-010 пилот)

- Профиль роста · единый `leadgen_tasks` (`plan` | `crm_signal`) · утренний бриф.
- CRM-сигналы → задачи (reply / next_action / remind_stale).
- Подготовка кандидатов кодом (`BriefCandidatePreparer`) → `AiChatClient` → валидация → `ai` | `rules` | `profile`.
- API: `/me/leadgen/profile|tasks|brief`, флаг `leadgen_pilot`, `X-Timezone`.
- Промпт: `resources/ai/leadgen/morning_brief.v1.*`.

### Ai (ADR-010)

- `AiChatClient` + `ai_runs` + retention 30/365 д · без цикла tool calling (оркестрация у потребителя).
- Потребители: LeadGen brief, Nutrition КБЖУ.

### Инфра

- `config/ai.php`, `config/leadgen.php` (лимит 6 AI-вызовов brief/сутки, 5 ручных refresh).
- Cron: `leadgen:brief-due` каждые 15 мин · `ai:purge-runs` daily.
- Job: `RefreshMorningBriefJob`.

## 5) Конфликты / риски (нужно решение)

| # | Риск | Предложение LLM-инженера |

| 1 | Дубли задач при `source=strategy` | Только `leadgen_tasks` + `dedupe_key`; новый enum source |

| 3 | PII в новых промптах | Общий маскер; `offer_note` — scrub перед LLM |
| 4 | Запись ИИ в CRM | Без нового ADR — не писать; HITL → trainer |
| 5 | Пилот-флаг | Все фичи РОП за `leadgen_pilot` (или новый gate — решение PO) |
| 6 | Календарь | Не считать scheduling источником задач, пока нет явной связи |
| 7 | Нет feedback по брифу | **Одна таблица сигналов тренера** + API (принял / отложил / отклонил / «спасибо, не нужно» / показанная поддержка). Закрывает сразу: веса скоринга, карту компетенций, поддержку тренера (§6). Не поля в `ai_runs` (тексты там живут 30 дней, это журнал вызовов модели) и не в брифах |

### Решения по конфликтам (блок A, 2026-10-08, PO + LLM-инженер)

| # | Тема | Решение |
|---|------|---------|
| 2 | Бюджет ИИ | **Раздельные лимиты по слоям** (блок Б): операционный, стратегический, инструментальный — каждый свой; слои не съедают бюджет друг друга. Значения — см. ниже |
| 4 | ИИ и CRM | ИИ готовит **черновик** заметки; в CRM пишет тренер после «ОК». Silent-записи `author_type=ai` нет |
| 6 | Календарь | Отложено: в MVP только «встреча / разбор» из плана, без связи с расписанием |
| 7 | Реакции тренера | v1: сделано / отложить / отклонить по пункту брифа + «спасибо, не нужно» на поддержку — один API |
| — | Потолок поддержки | Один вопрос в анкете «низкий / средний / высокий» = стартовый потолок |
| — | Прогресс в брифе | В MVP: факты за неделю из кода (ответы, диалоги, выполненные задачи) |
| 3 | ПДн | Решение LLM-инженера: общий маскер для всех промптов LeadGen; `offer_note` чистить перед отправкой в модель |

### Решения блока Б (2026-10-08)

| # | Тема | Решение |
|---|------|---------|
| 5 | Доступ | Все функции ИИ-РОП — за тем же флагом `leadgen_pilot`; выключение целиком — `ai.enabled` |
| 2 | Лимиты | Раздельные по слоям (операционный / стратегический / инструментальный) |
| — | Лимит исчерпан | Работаем без ИИ (бриф по правилам, черновики по шаблонам) + короткая пометка «лимит на сегодня исчерпан, завтра снова» |

**Лимиты (подтверждено PO, 2026-10-08):**

| Слой | Лимит | Почему |
|------|-------|--------|
| Операционный | 6 вызовов / сутки (крон + 5 обновлений; дельта — отсюда же) | Как пилот |
| Стратегический | ≤ 5 вызовов **на цикл**; ≤ 2 цикла / неделю | Редкий цикл, цепочка вызовов |
| Инструментальный | 20 вызовов / сутки | Частый, дешёвый; вызывает тренер |
| Образование, поддержка | без своего лимита | Шаблоны кода |
| Страховка | **3 ₽ / сутки** на тренера по всем слоям LeadGen | Защита от ошибки / дорогой модели |

Продуктовые вопросы волны 3 закрыты. Открыто для архитектора: модель данных (§5 №1, черновики, сигналы, оркестратор, счётчики) — [запрос](e-014-zapros-arhitektoru-volna-3.md).

## 6) Данные для сигналов состояния (поддержка тренера)

Волна 3 по [концепции поддержки](Агенты/Система-поддержки-тренера.md): проверить, есть ли данные для сигналов.

| Сигнал | В коде сейчас | Даёт уровень |
|--------|---------------|--------------|
| Выполненные задачи | ✅ `leadgen_tasks.done_at` | 1 |
| Касания и сдвиги по лидам | ✅ CRM: заметки, смена этапа, касания | 1 |
| Ручные обновления брифа | ✅ счётчик в `leadgen_morning_briefs` | слабый сигнал |
| Откладывания / отклонения задач | ❌ нет реакций на бриф (конфликт №7) | 2 |
| Реакция на поддержку («спасибо, не нужно») | ❌ | калибровка потолка |
| `metrics_daily` | ❌ | не нужен для уровня 1 на старте |
| Отдых / нагрузка тренера | ❌ расписание не связано с LeadGen | 3 |

**Вывод:**

- **Уровень 1** («за неделю — 5 ответов, 3 диалога») считается уже сейчас из `leadgen_tasks` + CRM. Цифры и текст — шаблон кода, LLM чисел не пишет.
- **Уровень 2** требует таблицы сигналов тренера (конфликт №7) и 2–4 недели данных.
- **Уровни 3–4** — данных нет, плюс зона самочувствия → только после отдельного решения PO + юриста.
- Сигналы состояния = поведенческие данные тренера; с уровня 2 — показать юристу (профилирование).
