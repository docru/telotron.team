## 2) §5.1 Операционный слой (бриф v2)

### 2.1 Источники задач

| Источник | Что берётся | `source` задачи |
|----------|-------------|-----------------|
| CRM | заявка без ответа; наступившая договорённость; «в работе» без касания N дней | `crm_signal` |
| Стратегия | пункты `sales_week_plans` / задачи `source=strategy` типов `strategy.*` | `strategy` |
| Календарь | в MVP **не отдельный источник**: договорённости уже приходят как CRM `next_action` | — |

Задачи анкеты `plan.*` в E-014 **не** создаются (техдок §8.1). Бриф v2 знает только `crm.*` + `strategy.*`.

### 2.2 Сбор → нормализация → скоринг (код)

1. Собрать открытые задачи на локальный день + просроченные (как пилот, до `candidates_max` ≈ 15).
2. Дедуп по `dedupe_key`; макросы `{{name_N}}` только для людей из кандидатов.
3. **Скоринг (черновик логики, веса — волна 6):** факторы из [Операционный-слой §6](Агенты/Операционный-слой.md) — просрочка, тип, стадия, давность касания, источник (стратегия — бонус), образовательный (в MVP: понижение, если тип «впервые» и есть более срочные CRM — не блокировать).
4. **Отсечение уровней** (обязательно, как T-138 §4.2): уровни 0 заявка → 1 договорённость → 2 remind → 3 стратегия. В модель уходит целый верх, пока `count < items_max(intensity)`.
5. Порядок типов внутри уровня стратегии — [типы §1](e-014-volna-4-tipy-i-kartochki.md).

### 2.3 Топ-N и Исполнитель

| | |
|--|--|
| Кандидаты в ИИ | после отсечения, ≤ 15; **не** включать `dismissed` / `carried_over` / `done` (техдок §3.4) |
| Пунктов в брифе | light 2 · moderate/intense 3 (или меньше, если кандидатов мало) |
| Роль ИИ | выбрать `task_id` из списка + `why` ≤ 120 символов (проверка кода ≤ 160) |
| Версия промпта | `sales.operational.brief.v2` (наследник `leadgen.morning_brief.v1`) |
| Схема ответа | без изменений: `{ items: [{ task_id, order, why }] }` — [schema](e-014-schemas/sales.operational.brief.v2.schema.json) |

### 2.4 Валидация и fallback

Как v1: `task_id` только из кандидатов; 1…N без повторов; `why` не пустой, без макросов имён, без стоп-фраз обещаний; обращение `ty`/`vy`. Нарушение → бриф **по правилам** (`source=rules`), пометка «без ИИ».

### 2.5 Дельта и кнопки (сверка с техдоком §3.3–3.4)

| Событие | Действие |
|---------|----------|
| CRM `reply_new_contact` / `next_action` (срок ≤ сегодня) / `remind_stale` после утра | Блок **«новое»**; `why` шаблоном; **без ИИ**; утренний `items` не трогать |
| «Сделано» | `brief_item.done` → задача `done` |
| «Отложить» | `postponed` → due завтра; в **последний день недели** у `strategy` → статус `carried_over` (в следующий план) |
| «Не сейчас» | `strategy` → `dismissed` до конца недели; `crm_signal` → скрыть на сегодня, завтра снова в кандидатах |
| Ручное «Обновить» | Полный пересчёт с ИИ (лимит); автопересчёт утра по `is_stale` — **выкл** |
| Монитор / Декомпозер | `dismissed` и `carried_over` в `plan_performance` = **не выполнено** |

### 2.6 Обратная связь (кнопки)

| Кнопка | Сигнал `TrainerSignalKind` | Эффект |
|--------|---------------------------|--------|
| Сделано | `brief_item.done` | задача done; CRM/стратегия по правилам |
| Отложить на завтра | `brief_item.postponed` | due → завтра; в скоринг 0 |
| Не сейчас | `brief_item.rejected` | скрыть из брифа дня; вес типа −1 (волна 6 — формула) |

Причина отклонения — **не** обязательна.

### 2.7 Fallback

Исполнитель упал / валидация / лимит / нет провайдера → бриф по правилам. Задач нет → «сегодня задач нет».

## 3) §5.2 Инструментальный слой

### 3.1 MVP vs после

| Инструмент | MVP | Проектируем |
|------------|-----|-------------|
| Черновик сообщения | **да** | — |
| Анализ ответа клиента | нет (ПДн клиента в модель + юрист) | да, контракт на потом |
| Разбор правок | нет | да, контракт на потом |
| Скриптовые (шаблон, ссылка записи, трекинг) | да, без ИИ | — |

### 3.2 Черновик сообщения (**v2 · пакетный**, техдок §5.2)

**Один вызов на задачу**, до 5 людей: ИИ пишет **каждому свой** текст по фактам (не шаблон с подставленным именем).

**Вход (код):** тип / цель; стиль; `constraints` (restriction); `people[]` — `{{name_N}}`, `source`, этап, дней с касания, 0–3 касания (дата/канал/тип) **без** текста переписки.

**Выход:** `drafts[]` `{ person_ref, body, alt_body }` + общий `why_so` (свёрнут). Код: ровно один draft на человека, тексты не дословно совпадают, TextGuard.

**HITL (MVP):** форма → «Скопировать» → «Я отправил» (касание в CRM). Отправка от платформы — после юриста.

**0 людей:** один draft с `person_ref = null`.

Промпт/схема: [draft_message.v2](e-014-prompts/sales.tools.draft_message.v2.system.txt) · [schema](e-014-schemas/sales.tools.draft_message.v2.schema.json). v1 оставлен как черновик итерации.

### 3.3 После MVP (кратко)

- **Анализ ответа:** вход — текст ответа клиента (согласие/предупреждение UI); выход `{tone, intent, suggested_action}`; только после вердикта юриста.
- **Разбор правок:** diff черновик vs отправленное; few-shot / обучение стиля.

## 4) §5.3 Образовательный слой (MVP)

### 4.1 Карта компетенций (черновик 8 навыков)

| Навык | Связь с типами задач |
|-------|----------------------|
| `reply_inbound` | ответ на заявку |
| `reactivate_base` | `base_reactivate` / тёплый круг |
| `follow_up` | напоминания |
| `offer_clarity` | `offer_setup`, `listing_setup` |
| `content_regular` | `content_post` / `content_short` |
| `referral_ask` | просьба рекомендовать |
| `partner_outreach` | партнёры |
| `review_collect` | отзывы |

Уровни по счётчику **выполненных** задач связанных типов: `0` впервые · `1` (1–3) · `2` уверенно (≥4). Обновляет **код** при `brief_item.done` / выполнении задачи. ИИ уровни не считает.

### 4.2 Форматы микро-обучения

| Формат | MVP |
|--------|-----|
| Принцип / чек-лист (коротко) | да, в свёрнутой подсказке |
| Пример чужого сообщения | опционально в `why_so` черновика |
| Разбор правок | нет |
| Отдельный пункт брифа «урок» | **нет** |

**Когда:** первая задача типа при уровне навыка `0` — показать свёрнутый блок «Как это сделать»; всегда доступно по «?» у задачи. **Не блокирует** действие.

### 4.3 Поддержка тренера (уровни 0–1)

По [Система-поддержки](Агенты/Система-поддержки-тренера.md): в MVP только **факты** в брифе (блок прогресса за неделю из агрегатов), без мотивационных фраз. Поля сигналов `care.*` — задел в схеме сигналов; UI температуры — не волна 5.

## 5) §5.4 Связка трёх слоёв

```
Стратегия (неделя) ──tasks strategy.*──▶ Операционный (день)
                                              │
                         brief items + кнопки │
                                              ▼
                                    Инструментальный
                                    (черновик по типу)
                                              │
                                    HITL форма → канал
                                              │
                                              ▼
                         сигналы ──▶ скоринг / навыки / стратегия
                         micro_learning ◀── счётчики навыков
```

| Поток | Содержание |
|-------|------------|
| Задач | Декомпозер → `sales_tasks` → CandidatePreparer → Executor → UI |
| Подсказок | навык 0 → свёрнутое микро + `why_so` у черновика |
| Обратной связи | done / postponed / rejected → `sales_trainer_signals` |
| HITL | сабмит черновика; отклонение пункта брифа; выбор стратегии (волна 4) |

## 6) §5.5 Оркестрация (черновик для архитектора)

| | |
|--|--|
| Граф дня | cron 07:00 TZ → compose brief → (опц.) Executor LLM → validate → save; днём CRM event → append «новое»; по запросу → draft_message |
| Сбой Executor | rules brief |
| Сбой draft | форма с пустым текстом + шаблон / ошибка «попробуйте снова»; задача остаётся |
| Лимиты (предложение) | brief: 1 cron + ≤5 manual/сутки (как пилот); draft: ≤20/сутки на тренера; общий ₽ потолок Sales |
| Логи | `ai_runs` (scenario `sales.operational.brief` / `sales.tools.draft_message`); `tool_runs` — мета вызова инструмента; тексты 30 дней |

## 8) Передать архитектору / юристу
