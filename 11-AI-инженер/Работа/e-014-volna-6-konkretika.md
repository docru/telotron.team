## 1. TaskScorer v1

### 1.1 Где скоринг в конвейере

Уровни T-138 **остаются жёсткими** (проверено eval волн 2–5: без них модель ставит план выше заявки). Скоринг **не перепрыгивает уровни** — он сортирует внутри уровня и отсекает слабое.

```
открытые задачи дня (без done / dismissed / carried_over; crm «Не сейчас» — скрыта сегодня)
  → балл каждой (код)
  → сортировка: уровень ↑, балл ↓, порядок типа ↑, id ↑
  → отсечение уровней: 0 заявки → 1 договорённости → 2 напоминания → 3 план, целыми уровнями, пока < items_max
  → пороги (§1.4)
  → ≤ candidates_max 15 → ИИ (brief.v2) или бриф по правилам = первые items_max
```

Пилотный `CandidatePreparer` меняется в одном месте: ключ сортировки `[rank, -overdue_days, id]` → `[tier, -score, rank, id]` + пороги.

### 1.2 Формула

```
score = max(0, тип + источник + просрочка + стадия + давность_касания + отложено + отклонено_тип + новый_навык)
```

| Фактор | Значение | К каким типам | Откуда данные |
|--------|----------|---------------|---------------|
| **тип** | заявка 30 · договорённость 25 · напоминание 15 · план: см. §1.3 | все | `sales_tasks.type` |
| **источник** | стратегия +15 · CRM 0 | все | `source` |
| **просрочка** | 10 / день; потолок: заявка 3 дня, договорённость 5 дней | `crm.reply_new_contact`, `crm.next_action` | заявка — локальная дата создания; договорённость — `next_action_at` |
| **стадия** | `new` 20 · `in_progress` 10 · `client` 10 · `former` 5 · `source = legacy_base` без касаний 5 | `crm.*` | `crm_contacts.status` / `source` |
| **давность касания** | 2 / день; потолок 20 дней | `crm.next_action`, `crm.remind_stale` | дней с `max(последнее crm_touches.occurred_at, created_at контакта)` |
| **отложено** | 1 раз +5 · 2 раза +10 · ≥3 раза **−10** | все | число `brief_item.postponed` по этой задаче |
| **отклонено (тип)** | план −10 за каждое, не ниже −20 · напоминание −5, не ниже −15 · заявка/договорённость — **не** штрафуются | все, кроме уровней 0–1 | `brief_item.rejected` по задачам того же типа за 14 дней |
| **новый навык** | −10 | `strategy.*`, если навык типа на уровне 0 **и** среди кандидатов есть уровень 0–1 | `sales_trainer_skills.level` (нет строки = 0); карта тип → навык — в JSON `type_skill` |

Смысл знаков:

- **Отложено 1–2 раза** — долг, чуть выше. **3+ раза** — тренер явно избегает; не навязываем, но и не удаляем.
- **«Не сейчас»** — штраф **типа** (не задачи): если тренер дважды за 2 недели отказался от напоминаний «по плану», такой тип уходит под порог, пока есть что-то лучше. Заявки и договорённости не штрафуем: это обязательства перед человеком.
- **Новый навык при срочной CRM** — в загруженный день новое ставим после привычного (не блокируем).

### 1.3 Веса типов плана

Порядок = порядок типов уровня 3 из [типов §1](e-014-volna-4-tipy-i-kartochki.md); при равенстве балла решает он.

| Тип | Вес | + источник = база |
|-----|-----|-------------------|
| `base_reactivate` | 20 | 35 |
| `follow_up` · `trial_convert` | 18 | 33 |
| `referral_ask` | 15 | 30 |
| `base_collect` · `offer_setup` | 12 | 27 |
| `link_share` · `partner_outreach` | 10 | 25 |
| `listing_setup` · `community_engage` | 8 | 23 |
| `content_post` | 6 | 21 |
| `content_short` · `social_profile` · `review_collect` | 5 | 20 |

Все типы плана без штрафов ≥ 20 — порог их не режет. Под порог уходят только с «Не сейчас», ≥3 переносами или новым навыком в загруженный день.

### 1.4 Пороги

| Порог | Правило |
|-------|---------|
| балл < **10** | убрать, если после этого остаётся хоть один кандидат |
| балл < **20** | убрать, если после этого остаётся **не меньше** `items_max` кандидатов |

Отсечение = откладывание: задача остаётся открытой и вернётся, когда штраф истечёт (14 дней) или станет нечего показать.

### 1.5 Хранение и лог

| Что | Предложение архитектору |
|-----|------------------------|
| Веса | `config/sales.php` → `sales.operational.scoring` (содержимое JSON v1) + `weights_version = sales.scoring.v1`. Таблица `sales_operational_scoring_weights` — **после MVP**, вместе с автокорректировкой |
| Лог расчёта | `sales_briefs.scoring` json: `{ weights_version, rows: [{ task_id, tier, score, factors, rank, included }] }` — хранится как бриф; отдельная таблица не нужна |
| Изменение весов | только новой версией (`v2`) в Git; в лог пишется версия |

### 1.6 После MVP: автокорректировка (не в коде волны 7)

`новый_вес_типа = старый × (1 + α × сигнал)`, α = 0,1; сигнал: done +1 · postponed 0 · rejected −1. Границы: вес типа в `[0,5 × стартовый; 2 × стартовый]`, пересчёт раз в неделю (после совещания), версия весов — на тренера. Старт — после 2–4 недель сигналов (решение PO). Тогда фактор «отклонено (тип)» из §1.2 убираем, чтобы не штрафовать дважды.

## 2. StrategyAudiencePicker: кого и сколько

Для `strategy.*` с черновиком сообщения без конкретного контакта (техдок §5.4).

### 2.1 Общие правила (все типы)

1. **Никогда:** `declined`; касание сегодня; у человека есть открытая `crm.*` задача (он уже в брифе); человек уже подобран в другую задачу плана сегодня (порядок задач — по баллу).
2. **Не третий раз без ответа** (карточка `ethics-and-law`): если после последнего «обычного» касания подряд ≥ 2 касания «Я отправил» из черновика — человека не берём. Нужна метка в `crm_touches.payload.source = sales_draft` (§4, пробел 1).
3. **Пауза по типу** (cooldown): человек не получал отправленный черновик **того же типа** N дней (таблица ниже).
4. **Сколько людей:** `N = min(число из пункта плана, если есть; N по интенсивности; 5)`; 5 — потолок пакетного `draft_message.v2`.
5. **0 людей** → один общий черновик без имени (как решено).
6. Тренер убирает/заменяет людей до генерации (техдок §5.4).

### 2.2 По типам

| Тип | Кого берём | Тишина | Пауза типа | Порядок | N light · moderate · intense |
|-----|-----------|--------|-----------|---------|------------------------------|
| `base_reactivate` | `former`; `source = legacy_base` (кроме `client`); `new` / `in_progress` без касания ≥ 30 дней | ≥ 30 дней или касаний нет | 30 дней | `former` → `legacy_base` → остальные; внутри — у кого касание свежее (теплее); без касаний — новые записи CRM первыми | 3 · 5 · 5 |
| `follow_up` | `new` / `in_progress`, `next_action_at` пусто или прошло | 3–29 дней | 7 дней | дольше молчит — первым | 3 · 5 · 5 |
| `trial_convert` | **MVP:** никого (в CRM нет отметки пробной) → общий черновик. После отметки: пробная 1–7 дней назад, не `client` | — | 14 дней | свежая пробная первой | 2 · 3 · 3 |
| `referral_ask` | `client`, в CRM ≥ 21 дня | — | 60 дней | дольше в клиентах — первым | 2 · 3 · 3 |
| `review_collect` *(принято PO 2026-10-15; в техдок §5.4 — архитектору)* | `client`, в CRM ≥ 30 дней | — | 90 дней | дольше в клиентах — первым | 2 · 3 · 3 |

Примечание к `follow_up`: `in_progress` от 7 дней (`stale_days`) уже получает свою задачу `crm.remind_stale` и правилом 1 исключается — пересечения нет.

Конфиг: `sales.tools.audience.{type}.{silence_min_days, silence_max_days, cooldown_days, n.{light,moderate,intense}}`, `sales.tools.audience.n_cap = 5`.

## 3. Шаблоны «зачем» (без ИИ)

Где: дельта «новое» (только `crm.*`) и бриф по правилам (`crm.*` + `strategy.*`). Файл — [sales.why-templates.v1.json](e-014-schemas/sales.why-templates.v1.json); в коде — рядом с `TaskType::whyTemplate()` (заменяет пилотные тексты `plan.*` в E-014).

Правила:

- одно предложение, ≤ 120 символов после подстановки (проверено скриптом, максимум 105);
- к тренеру — на «вы», как пилот (ты/вы из `communication_style` — только для сообщений клиентам);
- имя в **именительном** падеже (код не склоняет) — поэтому «Анна ждёт ответа», а не «заявка от Анны»;
- `{name}` — первое слово `display_name`, ≤ 20 символов; `{days}` — с согласованием («1 день», «3 дня», «12 дней»);
- выбор: `named_overdue` (есть имя и дней ≥ 1) → `named` → `default`.

| Тип | Текст |
|-----|-------|
| `crm.reply_new_contact` | Анна ждёт ответа на заявку уже 2 дня — с каждым днём шанс записи падает. / Анна ждёт ответа на заявку — чем быстрее ответ, тем выше шанс записи. / Новая заявка ждёт ответа — … |
| `crm.next_action` | Павел: договорённость просрочена на 2 дня — лучше закрыть её сегодня, пока доверие не остыло. / Мария: этот шаг вы обещали на сегодня — сделать его вовремя значит сдержать слово. / Сегодня срок договорённости — … |
| `crm.remind_stale` | Света без касания уже 12 дней — короткое сообщение вернёт разговор, пока интерес не остыл. / Человек давно без внимания — … |
| `strategy.base_reactivate` | Бывшие клиенты и знакомые вам уже доверяют — личное сообщение чаще всего даёт первые ответы. |
| `strategy.follow_up` | Многие отвечают только на второе сообщение — короткое напоминание возвращает разговор. |
| `strategy.trial_convert` | После пробной или живого отклика интерес самый высокий — самое время предложить следующий шаг. |
| `strategy.referral_ask` | Рекомендация довольного клиента — самое тёплое знакомство: новому человеку уже есть причина вам доверять. |
| `strategy.base_collect` | Люди, которые вас знают, откликаются охотнее всего — сначала соберём их в одном месте. |
| `strategy.offer_setup` | Понятное предложение и простая запись помогают записаться к вам без долгой переписки. |
| `strategy.link_share` | Ссылка на запись там, где вас видят, позволяет записаться без лишних вопросов. |
| `strategy.social_profile` | По профилю решают, писать ли вам, — понятная шапка и ссылка на запись снимают лишние вопросы. |
| `strategy.listing_setup` | На площадках услуг вас ищут люди с готовым запросом — понятная анкета помогает им написать. |
| `strategy.content_post` | Регулярные посты напоминают о вас и показывают, как проходят ваши занятия. |
| `strategy.content_short` | Короткие истории держат вас на виду у знакомых без больших затрат времени. |
| `strategy.community_engage` | Полезный ответ в тематическом или местном чате знакомит вас с людьми, которым это уже интересно. |
| `strategy.partner_outreach` | Партнёр рекомендует вас тем, кто ему доверяет, — это новые люди без рекламы. |
| `strategy.review_collect` | Отзывы и результаты клиентов отвечают на главный вопрос новых людей: «а мне это поможет?» |

## 8. Описание старых клиентов: «надиктуйте — ИИ осмыслит» (решение директора — MVP)

Идея и решения — [Идеи.md](Агенты/Идеи.md). Аналог — анкета тренера (`sales_intakes`, карточка «Вот что я понял»).

### 8.1 Сценарий

1. Список старых контактов собирается задачей `strategy.base_collect`.
2. Задача **`strategy.base_describe`** «Опишите старых клиентов: осталось N» открыта, пока есть неописанные старые контакты (`former` или `source = legacy_base`, кроме `declined`). Тренер добавил человека без описания → задача **снова открывается**. Создаёт и закрывает её **код**, не Декомпозер.
3. По одному человеку: «Расскажите об этом клиенте» → голос (распознавание **на клиенте**, `speech-recognition.ts`) или текст → на сервер только текст.
4. Вызов `sales.tools.describe_contact.v1` → поля + вопросы (≤ 2) о пустых обязательных.
5. Пока есть пустые обязательные — вопросы; ответ тренера → тот же вызов с `current` и `round + 1`.
6. Все обязательные заполнены → карточка «Проверьте, всё правильно по клиенту …» + **«Всё верно»**. Правка → вызов с `current` → снова карточка.
7. «Всё верно» → сохранить → следующий человек.

Как в анкете: если после 2 раундов вопросов что-то пусто — пустые поля в карточке становятся выбором из вариантов (enum), подтвердить нельзя, пока не выбрано. Это проверка кода, не модели.

### 8.2 Поля

| Обязательное | Значения |
|--------------|----------|
| `goal` | строка ≤ 100 · «не помню» |
| `period` | строка ≤ 60, словами тренера (без выдуманных дат) · «не помню» |
| `stop_reason` | `moved` · `money` · `time` · `motivation` · `result_reached` · `went_elsewhere` · `lost_contact` · `conflict` · `personal` · `other` · `unknown` (+ `stop_reason_note` ≤ 80) |
| `format_place` · `format_mode` | `online` · `offline` · `mixed` · `unknown` / `personal` · `group` · `mixed` · `unknown` |
| `parting` | `good` · `neutral` · `bad` · `unknown` |

Дополнительно: `result`, `liked`, `context[]` (≤ 5 фактов о жизни, которые тренер назвал сам).

**Не сохраняем:** здоровье (болезни, травмы, операции, диагнозы, беременность, лекарства), телефоны, адреса, ники, суммы, фамилии, имена других людей. Уход по здоровью → `personal` без примечания; флаг `health_mentioned` → UI: «О здоровье не сохраняем».

`unknown` — только когда тренер прямо сказал «не знаю». Молчание — `null` → вопрос.
