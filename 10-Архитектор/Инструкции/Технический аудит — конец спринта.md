# Технический аудит · конец спринта

**Обязанность архитектора (10).** Выполняется **в конце каждого спринта** — в связке с **retro** (последний рабочий день спринта или сразу после него).

**Регламент:** [Аджайл — процесс Telotron](../../01-Директор/Инструкции/Аджайл%20—%20процесс%20Telotron%20(регламент).md) · [Роль архитектора](Роль.md).

**Версия чеклиста:** v1.1 · 2026-07-05

---

## Зачем

Короткий срез «здоровья» кодовой базы и prod **по итогам спринта**, до планирования следующего. Не заменяет приёмку тестировщика и не блокирует retro, но **артефакт обязателен**.

Глубина — **пропорциональна изменениям спринта**. Если dev не было — фиксируем «без изменений кода» + быстрый sanity по prod/P0.

---

## Состав аудита (3 блока + итог)

| # | Блок | Вопрос спринта |
|---|------|----------------|
| **1** | **Архитектура** | Границы модулей, API, зоны; **PWA/build**; **миграции**; **docs drift**; ADR |
| **2** | **Безопасность** | Auth, секреты, ПД, rate limit; **compliance** — если трогали auth/legal |
| **3** | **Производительность** | N+1, тяжёлые запросы, bundle, offline/outbox |
| **Итог** | **Тесты (sanity)** + **action items** P0 / P1 / P2 | |

## Чеклист · 1. Архитектура

### Модули и контракты

- [ ] Изменения укладываются в [backend-архитектура](../../../_telotron.ru/docs/Техдок/01-канон-mvp/backend-архитектура-модулей-mvp.md) и [frontend-архитектура](../../../_telotron.ru/docs/Техдок/01-канон-mvp/frontend-архитектура-и-стек-mvp.md)
- [ ] Новые/изменённые эндпоинты — [api-http-контракт](../../../_telotron.ru/docs/Техдок/01-канон-mvp/api-http-контракт-mvp.md) или ADR на отклонение
- [ ] Нет «проброса» домена через чужие модули без явной границы
- [ ] Значимые решения — ADR или запись в журнале эпика/тикета

### PWA и зоны

- [ ] После правок SW / manifest / layout / precache — поднят **`build.pro`** и/или **`build.client`** в [`config/version.php`](../../../_telotron.ru/config/version.php) (по затронутой зоне)
- [ ] Зоны не смешаны: тема, домен, Pro-only не в Client bundle без lazy boundary
- [ ] После правок фронта — **`npm run build`** под `sail` ([Правила работы](../../03-Разработчик/Инструкции%20разработка/Правила%20работы.md))

### Миграции и совместимость

- [ ] Миграции обратимы **или** осознанно one-way (запись в отчёте)
- [ ] Нет destructive change для пользователей пилота без плана
- [ ] Seed/factory для локальной проверки не сломаны (если трогали схему)

### Docs drift

| Документ | Обновлён в спринте? |
|----------|---------------------|
| api-http-контракт | ☐ да / ☐ н/п / ☐ **отставание → action** |
| бизнес-модуль / техдок модуля | ☐ |
| ADR | ☐ |

- [ ] Техдолг архитектурного слоя: что отложили и почему

## Чеклист · 2. Безопасность

- [ ] Auth / invite / legal / ПД в зоне спринта — без очевидных дыр (IDOR, утечка scope, session fixation)
- [ ] Секреты не в Git; `.env` / compose — по канону
- [ ] Rate limit / anti-abuse на новых публичных или auth-маршрутах
- [ ] Audit trail при изменении акцептов или чувствительных данных ([T-011](../../backlog/сделано/T-011-legal-acceptances-audit-поля.md))

### Compliance (триггер: трогали reg / auth / legal)

*Если не касались — строка «н/п».*

- [ ] Сверка с [схемой акцептов](../../07-Юрист/Схема%20юрдокументов%20и%20этапы%20акцепта%20(Pro%20·%20Client).md)
- [ ] Записи `legal_acceptances` + audit-поля по канону
- [ ] Юр. вопросы эпика (напр. [T-066](../../backlog/бэклог/T-066-упрощение-входа-эпик.md)) — расхождения зафиксированы

- [ ] Замечания **P0/P1** → тикет или hotfix; **P2+** → backlog

---

## Чеклист · 3. Производительность

- [ ] Новые API: индексы, N+1 (eager load), пагинация где нужен список
- [ ] Тяжёлые операции не на критическом пути без необходимости
- [ ] Фронт: нет лишнего роста bundle; lazy routes сохранены
- [ ] Offline/outbox (Client): нет блокировки UI на retry; silent fail нет (если трогали Client)
- [ ] Замечания с evidence (запрос, метрика, скрин) — в отчёт

---

## Итог · тесты (sanity)

Не полное покрытие — только **зона изменений спринта**:

- [ ] Feature-тесты на затронутые API (happy + 1–2 негатива где уместно)
- [ ] Если меняли TS — `npm run test:ts` / smoke критичного экрана
- [ ] На исправленный баг — есть регрессионный тест **или** явная причина «нет»

| Статус | `OK` / `пробелы` |
|--------|-------------------|
| Комментарий | |

## Периодически (раз в 2–4 спринта, не каждый раз)

Отметить в отчёте «проверено» или «пропуск — спринт N»:

| Тема | Действие |
|------|----------|
| Зависимости | `composer audit` / npm advisories |
| Наблюдаемость | request_id, логи P0, webhook/боты |
| Техдолг | 3–5 пунктов из [техдолг-auth](../../../_telotron.ru/docs/Техдок/00-мета/техдолг-auth-после-этапа-1.md) / backlog |

**Не в спринтовый аудит:** полный pentest, нагрузочные тесты, полный UI-review (это тестировщик).
