## Критерии готовности

- [x] Пробы `openai-direct` (json_schema, 3 модели КБЖУ, `usage.cost`) — разблокирует часть B [T-135](../бэклог/T-135-e010-общий-ai-слой.md)
- [x] Промпт `leadgen.morning_brief` v1: вход (кандидаты, цифры воронки, до 10 людей под макросами, стиль из профиля), выход — JSON-схема `{items:[{task_id, order, why}]}`
- [x] Границы: только продвижение; без медицины и обещаний «N клиентов»; только задачи из кандидатов; макросы не ломать
- [x] Модель, температура, лимит длины `why`, таймаут — значения для конфига
- [x] Проверочный набор **20–30** ситуаций (новичок без людей, много заявок, всё просрочено, лёгкий план, нутрициолог…) без реальных ПДн
- [x] Прогон через шлюз Caila (тот же, что на stage): доля валидных ответов, доля «по правилам», среднее время, стоимость на бриф. Повтор из кода T-136 на stage — в [T-136](../бэклог/T-136-e010-утренний-бриф-бэкенд.md)
- [x] Отчёт в `11-AI-инженер/Работа/` + [чеклист перед AI-сервисом](../../11-AI-инженер/Инструкции/Чеклист-перед-AI-сервисом.md)

## Итог

Отчёт: [e-010-brief-prompt-v1-eval.md](../../11-AI-инженер/Работа/e-010-brief-prompt-v1-eval.md) · артефакты: [e-010-brief-eval/](../../11-AI-инженер/Работа/e-010-brief-eval/).

- **Шлюз `openai-direct`:** 3 модели КБЖУ работают; qwen — только с `reasoning: {"enabled": false}` и без `response_format`; gpt-4o-mini не отдаёт `usage.cost`.
- **Конфиг брифа:** `just-ai/openai-proxy/gpt-4o-mini`, temperature 0.2, max_tokens 400, таймаут 15 с, `why` ≤160 (цель 120), `leadgen.morning_brief.v1`.
- **Результат (25 ситуаций × 6, 150 вызовов):** валидно 100%, по правилам 100%, по ожиданиям 100%; 2,1 с в среднем, p95 ~2,6 с; ~0,036 ₽ за бриф.
- **Для T-136 обязательно:** сортировка кандидатов + отсечение нижних уровней приоритета до вызова модели; в `why` имён нет.
- **deepseek-v3.2 для брифа не годится** (34% валидных на strict-схеме).
- **Ограничение v1:** шаблонный текст `why` — оценить PO на пилоте, улучшать в v2.
