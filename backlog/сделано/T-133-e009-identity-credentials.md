## Контекст

Сейчас вход завязан на **телефон в записи человека**. На сайте телефон нужен; во ВК/других мини-приложениях — нет. Нужна модель: **человек** + **несколько способов входа**.

## Решения PO (уточнение)

| # | Решение |
|---|---------|
| A1 | В срезе T-133: способы входа = **телефон** + **ВК / ОК / MAX / Telegram**. Отпечаток и Google/Apple **не** переносим |
| A2 | Телефон **только** в способах входа (без копии на человеке) |
| A3 | Два независимых входа без связи = **два человека**; **полной склейки историй в T-133 нет** |
| A4 | Отдельный ADR-009 «человек + способы входа» (accepted до миграции) |
| A5 | MAX/Telegram **для кодов/уведомлений** на человеке в T-133 **не трогаем** |
| B1 | Одна таблица способов входа, у записи пометка зоны Pro или Client |
| B2 | Один id ВК в Pro и в Client — **разные** привязки (зоны не смешиваем) |
| B3 | Имя в коде/БД: **`auth_methods`** (в текстах — «способы входа») |
| B4 | Столбец `users.phone` — на **переходный период**, потом убрать; для входа уже не использовать |
| C1 | На сайте (PWA) без телефона войти/зарегистрироваться **нельзя** |
| C2 / D | «Один кабинет» сайт+ВК — не в T-133; см. **[T-134](T-134-e009-связка-аккаунтов.md)** (блокер пилота) |
| C3 | Отпечаток / Face ID — оставить как сейчас |
| C4 | T-133 = фундамент; **вход через ВК** — [T-130](T-130-e009-auth-launch-token.md) |

## Модель

| Сущность | Смысл |
|----------|--------|
| **User** (человек) | Профиль зоны; **без** обязательного телефона |
| **`auth_methods`** | Способ входа: тип + внешний id + зона; N на человека |

Типы в срезе: `phone`, `vk`, `ok`, `max`, `telegram` (как вход в мини-приложение; не путать с chat_id для OTP).

Правила:

1. Вход ищет способ нужного типа, не «обязательный phone на User».
2. Один человек — много способов; один способ → один человек в рамках зоны.
3. Уникальность: `(zone, type, external_id)` уникален.

## Критерии готовности

- [x] ADR-009 «человек + способы входа» (proposed→accepted)
- [x] Таблица `auth_methods` + модель/сервис
- [x] Перенос существующих телефонов в `auth_methods` (тип `phone`)
- [x] Вход/регистрация PWA через `auth_methods` (регресс OTP и т.д.)
- [x] Можно создать человека **без** телефона + способ `vk` (готовность для T-130)
- [x] `users.phone` не используется для входа; колонка ещё может жить переходный период (dual-write)
- [x] Тесты: несколько способов; изоляция зон; PWA без phone-метода не логинит (`AuthMethodServiceTest`, `AuthMethodsPhoneLoginTest`)
- [x] `api-http` / техдок Identity обновлены
