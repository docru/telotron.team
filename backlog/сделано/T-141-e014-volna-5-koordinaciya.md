## Контекст

Волна 4 задала вход: план недели и типы `strategy.*` попадают в бриф. Волна 5 — **детальное проектирование** трёх слоёв **в связке** ([Этапы.md §5](../../11-AI-инженер/Работа/Агенты/Этапы.md)):

1. **Операционный** — бриф v2 (источники, скоринг, топ-N, Исполнитель, дельта, feedback, fallback).
2. **Инструментальный** — черновик / анализ ответа / разбор правок, два режима, HITL, `tool_runs`.
3. **Образовательный** — карта компетенций, микро-обучение, связь с задачами и режимами, `micro_learning`.

**Критерий волны:** три слоя спроектированы, понятно, как работают вместе (потоки задач / подсказок / обратной связи + HITL).  
**Не эта волна:** финальные числа весов и тексты промптов (волна 6), код (волна 7), перенос карточек в `resources/sales/knowledge/`, must юриста перед prod.

Принцип: **код решает, ИИ объясняет**. Имена — по [глоссарию Sales](../../../_telotron.ru/docs/Техдок/03-модули/sales-глоссарий-и-нейминг.md).

## Порядок работ

```
① Операционный слой     → AI + архитектор параллельно; PO — развилки (топ-N, кнопки)
② Инструментальный      → AI (промпты/валидация) + архитектор (вызовы, tool_runs); PO — режимы / HITL
③ Образовательный       → AI (карта, форматы) + PO (когда показывать)
④ Связка + оркестрация  → архитектор ведёт; AI сверяет контракты
⑤ Accept волны 5        → критерий §5; журнал здесь; статус → done
```

Почему так: операционный — потребитель плана стратегии и ежедневная точка входа; инструменты вызываются из задач брифа; образование пронизывает оба.
