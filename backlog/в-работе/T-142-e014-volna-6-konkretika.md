## Контекст

Волна 5 зафиксировала механизмы дня. Волна 6 — **числа и тексты**, которые код и ИИ будут использовать без invent-on-the-fly.

Канон входа: [техдок дня §11](../../../_telotron.ru/docs/Техдок/03-модули/sales-день-бриф-инструменты-обучение.md) + [Этапы §6](../../11-AI-инженер/Работа/Агенты/Этапы.md).

## Порядок работ

```
① Скоринг TaskScorer          → AI: факторы/веса/пороги/α; архитектор: версия в конфиге/таблице
② Шаблоны «зачем» (why)       → AI: crm.* + strategy.* для дельты и fallback без ИИ
③ Полировка промптов дня      → AI: brief.v2 + draft_message.v2 + расширение eval
④ Микро-уроки (8 навыков)     → AI тексты; PO тон/длина
⑤ Пороги AudiencePicker       → AI предложение N; архитектор в техдок
⑥ Схемы полей / анкета (хвост)→ сверка с техдоком; только пробелы
⑦ Accept волны 6              → критерий §6; журнал; → волна 7
```

Параллельно с ①–② можно начинать ④. Код не стартует до accept T-142 (кроме уже согласованного переноса knowledge — отдельный тикет).

## Кто что делает

### AI-инженер (ведущий)

- [ ] **§6.1 Скоринг:** список факторов `TaskScorer`; стартовые веса; формула `score = Σ(фактор × вес)`; пороги отсечения; штраф `rejected` / учёт `postponed`; skill 0 (понижение при срочных CRM); формула корректировки `новый = старый × (1 + α × сигнал)` + стартовое α
- [ ] Версия весов → документ + контракт для `sales_operational_scoring_weights` (как в техдоке)
- [ ] **§6.4 Шаблоны why:** готовые «зачем» для дельты и брифа по правилам по каждому типу `crm.*` / `strategy.*` (без ИИ)
- [ ] **Полировка:** `sales.operational.brief` v2 и `sales.tools.draft_message` v2 — правки по eval/продукту; расширить eval draft
- [ ] **§6.5 Микро-уроки:** тексты по 8 навыкам (пример / принцип / чек-лист — по формату волны 5)
- [ ] **Пороги N** в `StrategyAudiencePicker` (сколько людей подбирать)
- [ ] Рабочий документ волны 6 (числа + тексты) + передача архитектору пунктов в техдок
- [ ] Перенос карточек в `resources/sales/knowledge/` — **если** не вынесен отдельным тикетом; иначе ссылка на него

### Архитектор

- [ ] Зафиксировать в техдоке: таблица/конфиг весов + версия; пороги AudiencePicker; уточнение полей схем, если AI найдёт дыры (§6.6)
- [ ] Не проектировать заново день — только конкретика поверх accepted техдока волны 5
