## 1) Зачем

Клиент вводит название (домашняя еда, кафе). Эластичный поиск по **пользовательским** и **ИИ**-таблицам; ИИ — **по клику**. Mean + **95% ДИ по всем 4**, маркер «ИИ». Крауд-правки (E2+E3): подмножество ≥3 с разбросом &lt;5% → среднее в `by_users`.

---

## Передача разработчику (канон)

1. **Таблицы:** `nutrition_products_ai_estimates`, `nutrition_products_by_users`, staging правок (имя на усмотрение, связь с эстимейтом). `nutrition_products` в потоке **не использовать** (на сервере можно оставить).
2. **Поиск:** эластичный по `by_users` + `ai_estimates`; нормализация **B** (правила + fuzzy). **D** (aliases) — позже.
3. **ИИ:** Caila; **3 модели** параллельно, **1 промпт** (Q23): **Deepseek V3.2** + **Qwen3.5 Flash 02.23** + **Gpt 4o Mini**. КБЖУ на **100 г**; mean + 95% ДИ по всем 4.
4. **UX:** сканер/barcode-код **удалить**; слот → лупа+ИИ (inactive→active после паузы); «Искать с ИИ» в конце выдачи + empty state; компакт `К…Б…Ж…У…ИИ` + лайтбокс (вписать в wireframe T-108); лоадер; сбой → «не удалось найти»; лимит → тихо; Pro видит ИИ так же.
5. **Лимит:** 50 **ансамблей**/user/сутки, полночь по **серверу** (сейчас UTC); hit БД не считается.
6. **Правка руками:** на блюде без ИИ/ДИ; staging; **1 правка / user / эстимейт**; promote E2 (&lt;5% max−min по всем 4 → mean) → `by_users`, удалить staging + `ai_estimates`.
7. **Ключи** только на сервере; логи request_id / модель / latency; тесты; techdoc; `build.client` при UI.

## 2) Канон из черновика ТЗ (черновик → уточняется)

### Когда запускать ИИ

1. Нормализация названия (правила + fuzzy, схема B).
2. Эластичный поиск по **`nutrition_products_by_users`** и **`nutrition_products_ai_estimates`** (не по `nutrition_products`; **без штрихкода**).
3. Hit в `by_users` → отдать как утверждённые пользовательские данные, **ИИ не звать**.
4. Hit в `ai_estimates` → отдать ИИ-оценку (+ ДИ), **ИИ не звать**.
5. ИИ — **только по клику** (лупа+ИИ / «Искать с ИИ» / empty state) → ансамбль → сохранить в `nutrition_products_ai_estimates` → показать.

### Таблицы (канон Q8 / Q9)

| Таблица | Назначение |
|--------|------------|
| `nutrition_products_ai_estimates` | Оценки ансамбля ИИ (на 100 г) + ДИ |
| `nutrition_products_by_users` | Утверждённые КБЖУ из согласованных правок пользователей |
| *(staging, имя уточнить)* | Правки пользователей, **не совпавшие** с найденным эстимейтом; связь с `ai_estimates` |
| `nutrition_products` | **Не используем** в этом потоке; на сервере пока оставляем |

**Крауд-утверждение (E2+E3):** правка ≠ эстимейт → staging (связь с эстимейтом); **не более 1 правки на пользователя на эстимейт**. Среди staging ищем подмножество **≥3**, у которого по **каждому** из 4 макросов **max−min &lt; 5%** → в `by_users` пишем **среднее**; эти staging и связанный `ai_estimates` **удаляем**. Выбросы остаются и не блокируют promote.

### Ансамбль

- Минимум **3** успешных ответа (**3 разные модели**, один общий промпт; через Caila).
- **Фикс моделей (Q23, 2026-08-08)** — каталог Caila / `caila-llm-prices.csv`; точные model id в `NUTRITION_AI_MODELS`:

  | # | Модель (каталог) | Вендор / сервис | Вход / выход ₽/1М (ориентир) | Роль |
  |---|------------------|-----------------|------------------------------|------|
  | 1 | **Deepseek V3.2** | DEEPSEEK / OPENROUTER | 31,3 / 46,9 | якорь качества + JSON |
  | 2 | **Qwen3.5 Flash 02.23** | ALIBABA / OPENROUTER | 8,1 / 32,3 | RU + скорость, дешёвый слот |
  | 3 | **Gpt 4o Mini** | OPENAI / OPENROUTER (или OPENAI) | 18,6 / 74,5 | западный якорь, structured output |

  Оценка бюджета (≈200 in + 80 out на модель): ансамбль **~0,02 ₽**; 10 000 ансамблей/сутки ≈ **~200 ₽/день**. Не брать Thinking/R1, VL, Coder, 7B-класс (слабый JSON/RU).
- Параллельные запросы; таймаут на модель (цель ≤5 с на одну; UX ≤10 с на весь ответ).
- Агрегация: mean по ккал/Б/Ж/У; **95% ДИ** (`mean ± 1.96·std/√n`) **по всем четырём** показателям.
- Успешных ответов **&lt; 2** → оценка не считается, сообщение пользователю.
- Невалидный JSON / ошибка модели → исключить из расчёта, залогировать.

### Вывод UI (форма блюда)

- В форме есть **поля ввода КБЖУ**.
- **Выше** — компакт: `К1800 Б12 Ж10 У18 ИИ`; тап → лайтбокс со всеми 95% ДИ и пояснением.
- Если пользователь **сам меняет хотя бы одно** поле КБЖУ → приписка **ИИ** и ДИ **пропадают**; в приём пищи — его цифры.
- Если правка **не совпадает** с найденным эстимейтом → в staging (см. таблицы выше); при 3 одинаковых — promote в `by_users`.
- Без мед. обещаний (см. идею границы Минздрава).

### Сохранение

- Повторный запрос по тому же нормализованному имени → из БД (без новых вызовов ИИ). Redis на MVP **не** используем.
- Пометка, что источник — ИИ (`kbju_source = ai_estimate` и/или `is_ai_estimate`).

### MVP поставки (из ТЗ, уточняется)

1. **Caila** + **3 модели** (Deepseek V3.2 / Qwen3.5 Flash / Gpt 4o Mini) параллельно, **один** промпт.  
2. Сохранение в БД + ДИ в UI.  
3. Позже: A/B и подмена id в `NUTRITION_AI_MODELS` без смены контракта (при необходимости — дешевле/сильнее из каталога).

### UX: когда звать ИИ (черновик Q13)

Пользователь сам знает, что название **завершено** → ИИ только **по клику**, не на каждый символ.

| Вариант | Суть |
|---------|------|
| **1** | Вместо штрихкода — неактивная «лупа+ИИ»; после паузы в наборе — активна |
| **2** | В конце эластичной выдачи отдельная строка **«Искать с ИИ»** (визуально не как обычный hit) |
| **1+2** | Оба сразу |
| **3** *(доп.)* | Штрихкод **оставить**; рядом/под полем чип **«Оценить с ИИ»** (активен после паузы / при непустом имени) |
| **4** *(доп.)* | Пустая выдача: «Ничего не найдено» + главная кнопка **«Оценить с ИИ»** |

**Решение PO:** **1 + 2 + empty state.** Сканер убрать; слот → лупа+ИИ. Код штрихкода — **вычистить** (вернуть позже с нуля при необходимости).

---

### Крауд: выбросы (черновик к Q28/Q29)

Проблема: если кластер «растягивать» по крайним, один кривой ввод ломает порог 5% → куча растёт без promote.

| Вариант | Суть |
|---------|------|
| **E1. Несколько кластеров** | Голос входит в кластер только если в пределах 5% от **медианы/среднего кластера** (не раздуваем крайние). Иначе — **новый** кластер у того же эстимейта. Promote: любой кластер из **≥3** → mean; outlier-кластеры остаются |
| **E2. Подмножество из всех** | Копим все правки; ищем любое подмножество **≥3**, у которого по каждому макросу **max−min &lt; 5%** → mean → promote. Кривые сами отваливаются |
| **E3. 1 правка / пользователь / эстимейт** | Антиспам + меньше шума (комбинируется с E1/E2) |
| **E4. TTL** | Staging старше N дней удалять (опц.) |

**Решение PO:** **E2 + E3**.

---

### Нормализация имён (черновик к Q22)

Проблема: эластичный поиск + опечатки → много почти одинаковых записей в `nutrition_products_ai_estimates`.

| Вариант | Суть | Плюсы | Минусы |
|---------|------|-------|--------|
| **A. Правила** | lower, trim, пробелы, ё→е, пунктуация; опц. лёгкий стемминг RU | дёшево, предсказуемо | «круасан» ≠ «круассан» без fuzzy |
| **B. Правила + fuzzy к существующим** | сначала A; потом поиск похожих в `ai_estimates` **и** `by_users` (порог сходства); hit → reuse | меньше дублей и денег | порог ошибается |
| **C. Дешёвая LLM-канонизация** | один короткий вызов Caila → канон. имя → ансамбль / поиск | лучше чинит опечатки | +latency, +деньги |
| **D. Канон + aliases** | `canonical_name` + aliases | повторные опечатки сходятся | сложнее модель |

Рекомендация на MVP: **B** (A обязательно внутри). C — если B часто мимо. D можно нарастить поверх B.

**Решение PO:** MVP = **B**; **D** — после MVP.
