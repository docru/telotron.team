## 1) Зачем

Voice Password / звонок на пилоте часто **не доходит сразу** → пользователь ждёт и отваливается. OAuth (VK / Яндекс) даёт вход с **минимальным трением и минимальными тратами** на OTP; телефон остаётся якорем учётки и запасным способом входа.

---

## 2) Канон (черновик до закрытия Q)

### Вход (экран)

1. **Основное:** «Войти через Яндекс» и «Войти через VK» — **равноправно рядом**.
2. **Запасное:** ссылка **«Войти по телефону»** под кнопками OAuth → OTP **только звонком** (Voice / Flash Call).
3. Passkey — на повторном входе (как сейчас), если уже был успешный вход.

### После OAuth

| Ситуация | Поведение |
|----------|-----------|
| Провайдер **отдал телефон** | Показать **имя + номер** из профиля провайдера → «Это вы / номер актуален?» **Да** → вход/reg **без** нашего OTP. **Нет / другой** → ввод номера + наш OTP |
| Провайдер **не отдал телефон** | Ввод номера + наш OTP |
| Номер **уже есть** у другой учётки | Предложить **склейку**: OTP на номер → привязать OAuth к **существующей** учётке (черновую User не создаём) |
| Номер свободен, User нет | Регистрация (legal + профиль); **имя подставить** из провайдера; OAuth привязан |

### Привязка второго канала

Пользователь входит одним каналом; **второй** привязывает позже в **своём кабинете** (профиль). Один телефон = одна учётка; OAuth — способы входа, не отдельные User.

### Якорь

- **Primary key учётки:** телефон (E.164), как сейчас.
- OAuth: таблица связей `user_id` ↔ `provider` + `provider_user_id` (+ метаданные).
- «Verified у VK/Яндекс» + «номер актуален» → пометка **oauth** (не эквивалент нашего звонка); юр. формулировки осторожно.

## 3) Решения PO

Прогресс уточнения: **Q1–Q17 ✅** · wireframe черновик

### Client · инвайт (Q15–Q16)

| Состояние | Экран |
|-----------|--------|
| Нет отметки «уже входил» на устройстве | Нужно приглашение + поле вставить ссылку |
| Есть отметка «уже входил» | Форма входа (VK / Яндекс / телефон) |
| Reg не закончена, но **инвайт есть** в localStorage | Форму инвайта **не** показывать — продолжаем вход/reg |
| Reg не закончена и **инвайта нет** | Снова форма инвайта |

Инвайт: сохраняется с лендинга `/i/{token}`; сбрасывается после успешного accept при входе/reg или при переходе по другой ссылке-инвайту (текущее поведение `telotron.client.onboarding_invite.v1`).
