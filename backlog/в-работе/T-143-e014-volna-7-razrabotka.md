## MVP в scope

| Слой | Что в код |
|------|-----------|
| Фундамент | Миграции таблиц Sales strategic + day; сигналы тренера; `sales:knowledge-sync`; файлы `resources/sales/` (knowledge, why, lessons, weights); промпты в `resources/ai/sales/`; валидаторы; лимиты |
| Стратегический | Intake → Диагност → Стратег → выбор → Декомпозер → план недели → Монитор / совещание; UI онбординга |
| Операционный | Бриф v2 (CRM + стратегия), `TaskScorer` веса v1, дельта «новое», кнопки → сигналы, факты прогресса 0–1 |
| Инструменты | `draft_message` v2 (копировать + «Я отправил»); `describe_contact` + задача `base_describe` |
| Обучение | Счётчики `sales_trainer_skills`; свёрнутые микро-уроки |

## Вне MVP (не резать в первой пачке)

- Анализ ответа / разбор правок · outbound от платформы (§31) · α-корректировка весов · few-shot таблица · поддержка уровней 2–4

## Последовательность (кто → кому)

```
Шаг 0  Архитектор (+ PO) ─── нарезка тикетов T-14x по срезам A–F ниже
          │
Шаг 1  Dev ─── Срез A · фундамент (миграции, sync, конфиг, промпты в Git)
       AI  ─── параллельно: перенос артефактов волны 4–6 в resources/ + чеклист AI
          │
Шаг 2  Dev ─── Срез B · стратегический слой (бэкенд + API)
       Dev/UI── Срез B.ui · онбординг / выбор / план / совещание (после или внахлёст с API)
          │  PO: приёмка «тренер выбрал стратегию и видит план недели»
Шаг 3  Dev ─── Срез C · операционный бриф v2 + скоринг + дельта + кнопки
          │  PO: приёмка «бриф за день из CRM + плана»
Шаг 4  Dev ─── Срез D · draft_message + describe_contact
          │  PO: приёмка «черновик + описание старых»
Шаг 5  Dev ─── Срез E · навыки + микро-уроки + факты прогресса в брифе
          │
Шаг 6  QA (+ AI smoke) ─── регрессия пилота E-010 + eval strategic/brief/draft/describe
          │
Шаг 7  Директор / PO ─── accept MVP E-014 на стенде → prep prod (юрист must, ops)
```

| Шаг | Кто | Что | Вход | Критерий среза |

| 0 | **Архитектор** + **PO** | Нарезать тикеты по срезам A–F; зафиксировать ветку `initiative/i-001…` / порядок merge; не трогать поведение пилота до feature-flag | техдоки + T-142 артефакты | список T-XXX в E-014 / бэклоге |
| 1 | **Dev** + **AI** | **A · Фундамент:** таблицы, enum типов, сигналы, knowledge-sync, weights/why/lessons/prompts в `resources/`, оркестратор-заготовка, валидаторы из проверок AI | [T-142](../сделано/T-142-e014-volna-6-konkretika.md) файлы | `sales:knowledge-sync` зелёный; миграции; промпты читаются кодом |
| 2 | **Dev** | **B · Стратегия:** цикл агентов + API + UI выбора/плана/совещания; RuleStrategy / TemplateWeekPlanner как fallback | техдок стратегии | тренер проходит онбординг → выбирает стратегию → видит план; при сбое ИИ — путь по правилам |
| 3 | **Dev** | **C · День / бриф v2:** CandidatePreparer + TaskScorer v1 + Исполнитель + дельта + кнопки | техдок дня §3 | бриф light 2 / mod–int 3; стратегия в кандидатах; «новое» без ИИ; сигналы пишутся |
| 4 | **Dev** | **D · Инструменты:** draft (пакетный) + copy/sent; describe_contact + ContactDescribeTaskSync | техдок дня §5 | черновик на N людей; описание контакта → `profile`; задача `base_describe` живёт по правилам |
| 5 | **Dev** | **E · Обучение + поддержка 0–1:** skills, lessons API/UI, блок фактов прогресса в брифе | уроки T-142 | skill 0 → свёрнутая подсказка; цифры прогресса из кода |

| 7 | **Директор / PO** | Accept MVP | отчёт QA | T-143 → done или «хвосты ops/legal»; нарезка prod |

## Кто что делает (чеклист)

### Архитектор

- [ ] Шаг 0: нарезка тикетов A–E (+ отдельный на knowledge/prompts если нужно)
- [ ] Ревью границ модулей / миграций по мере PR
- [ ] Feature-flag / условие выкладки: пилот vs E-014
- [ ] Follow-up пробелов схем из техдока (`audience_n`, направление касания CRM) — в тикетах или явно «после MVP»

### Разработчик

- [ ] Срезы A → E по порядку (B.ui можно параллелить с B API после контракта)
- [ ] Не включать outbound / analyze_reply
- [ ] Тесты на каждый срез

### AI-инженер

- [ ] Перенос в репо: knowledge-карточки, why, lessons, weights, промпты/схемы strategic + brief + draft + describe
- [ ] Smoke / eval на стенде после срезов B–D
- [ ] Чеклист перед AI-сервисом для новых сценариев

### PO

- [ ] Приёмка срезов B, C, D (минимум)
- [ ] Тексты UI / пустые состояния — не блокировать фундамент

### QA

- [ ] Регрессия E-010 + сценарии E-014 MVP
- [ ] E2E критичного пути: стратегия → бриф → черновик

### Юрист (параллельно, не блокер старта кода)

- [ ] Must перед prod: opt-in ИИ, политика/Caila, UI рассказа (§25–30, §32)
- [ ] §31 — только если включаем outbound (не MVP)

## Критерии готовности (accept T-143 = MVP E-014 на стенде)

- [ ] Стратегия выбирается тренером; план недели создаётся; fallback без ИИ работает
- [ ] Бриф v2: CRM + задачи стратегии; скоринг v1; дельта; кнопки → сигналы
- [ ] Черновик сообщения + описание старых клиентов
- [ ] Навыки + микро-уроки; прогресс в брифе из кода
- [ ] Пилот E-010 на тренерах без флага E-014 не сломан
- [ ] Лимиты и PII-макросы соблюдены; ключи не в логах
- [ ] Запись в E-014 / Этапы — волна 7 MVP закрыта (или «код ✅, prod ⬜»)
