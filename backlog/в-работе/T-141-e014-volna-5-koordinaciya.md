## Контекст

Волна 4 задала вход: план недели и типы `strategy.*` попадают в бриф. Волна 5 — **детальное проектирование** трёх слоёв **в связке** ([Этапы.md §5](../../11-AI-инженер/Работа/Агенты/Этапы.md)):

1. **Операционный** — бриф v2 (источники, скоринг, топ-N, Исполнитель, дельта, feedback, fallback).
2. **Инструментальный** — черновик / анализ ответа / разбор правок, два режима, HITL, `tool_runs`.
3. **Образовательный** — карта компетенций, микро-обучение, связь с задачами и режимами, `micro_learning`.

**Критерий волны:** три слоя спроектированы, понятно, как работают вместе (потоки задач / подсказок / обратной связи + HITL).  
**Не эта волна:** финальные числа весов и тексты промптов (волна 6), код (волна 7), перенос карточек в `resources/sales/knowledge/`, must юриста перед prod.

Принцип: **код решает, ИИ объясняет**. Имена — по [глоссарию Sales](../../../_telotron.ru/docs/Техдок/03-модули/sales-глоссарий-и-нейминг.md).

## Порядок работ

```
① Операционный слой     → AI + архитектор параллельно; PO — развилки (топ-N, кнопки)
② Инструментальный      → AI (промпты/валидация) + архитектор (вызовы, tool_runs); PO — режимы / HITL
③ Образовательный       → AI (карта, форматы) + PO (когда показывать)
④ Связка + оркестрация  → архитектор ведёт; AI сверяет контракты
⑤ Accept волны 5        → критерий §5; журнал здесь; статус → done
```

Почему так: операционный — потребитель плана стратегии и ежедневная точка входа; инструменты вызываются из задач брифа; образование пронизывает оба.

## Кто что делает

### AI-инженер

- [ ] **§5.1 Операционный:** источники (CRM + стратегия + календарь) → сбор/дедуп → факторы скоринга (черновик логики, без финальных весов) → топ-N → контракт промпта Исполнителя (**бриф v2**, новые `TaskType`) → валидация → дельта → сигналы обратной связи → fallback
- [ ] Обновление проверочного набора брифа (наследник T-138) под v2 / новые типы
- [ ] **§5.2 Инструментальный:** список инструментов ↔ типы задач; промпты/схемы/валидация для черновика, анализа ответа, разбора правок; правила двух режимов
- [ ] **§5.3 Образовательный:** черновик карты компетенций (5–10 навыков); форматы микро-обучения; когда предлагать; правило «не блокирует»
- [ ] Рабочий документ волны 5 (аналог `e-014-volna-4-strategicheskiy-sloy.md`) + передача архитектору пунктов в техдок

### Архитектор

- [ ] Техдок операционного слоя / расширения Sales: `CandidatePreparer` (план недели + CRM), дельта, сигналы тренера (общая таблица), лимиты по слоям
- [ ] Техдок инструментального: граф вызовов из брифа/задачи, HITL утверждения, `tool_runs`, fallback
- [ ] Техдок образовательного: `micro_learning`, связь с задачами/режимами (без блокировки UX)
- [ ] **§5.4–5.5 Связка + оркестрация:** потоки, граф агентов, сбои, лимиты, логирование
- [ ] При необходимости — дополнение ADR-011 / api-http (новые эндпоинты сигналов, tools)

### PO

- [ ] Топ-N задач в брифе (1–3 или иначе)
- [ ] Кнопки / сигналы обратной связи (принял / отложил / отклонил / …)
- [ ] Режимы «сделай за меня» / «покажи, как» — кто выбирает (тренер / система / прогресс)
- [ ] Где HITL обязателен (отправка черновика — да; подсказка обучения — нет)
- [ ] Когда показывать микро-обучение (не мешать действию)
- [ ] Поддержка тренера MVP (уровни 0–1) — стык с брифом, без новой волны мотивации

### Юрист (по запросу, не блокер старта)

- [ ] Только если всплывут новые риски по черновикам сообщений / разбору диалогов / сигналам (поверх §25–30 волны 4)
- [ ] Must UI/политики / opt-in — **не** scope T-141 (перед prod E-014)

### Разработчик

- Не волна 5. Реализация — волна 7 по утверждённому техдоку. Подтикеты кода — отдельно.
