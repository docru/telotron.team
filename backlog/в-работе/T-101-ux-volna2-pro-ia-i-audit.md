## Решение директора (зафиксировано)

Дата: **2026-07-31**.

1. Убрать главную Pro; по умолчанию — **Клиенты**.
2. Табы: **Клиенты** · **Расписание** · **Кабинет** · **Поддержка**.
3. В **Кабинет**: тренировки, планы питания, группы, профиль. Смысл: место, где тренер **самостоятельно готовится к работе**.
4. В поддержку: обратная связь, опросы. **«Знакомство с Телотрон» — убрать.**
5. Планы питания: форма → **«+»** справа сверху.
6. На хабах Кабинет/Поддержка — крупная навигационная ориентация («крошки» / title stack).
7. Профиль: вход из **Кабинета** и **компактный аватар в шапке** (оба на один экран). Полностью из шапки **не** убирать (уточнение 31.07 · вариант A).
8. Карточка клиента — **сводная** (канон ниже) + плитки в подробные разделы.
9. Мастера онбординга — **полное удаление**; подсказки — [T-102](../бэклог/T-102-ux-виджет-мягких-подсказок.md).

### Канон сводки карточки клиента (A1) · 2026-07-31

Согласовано с директором.

**Слои (сверху вниз):**

1. **Кто:** имя, аватар, возраст / ДР (как сейчас по смыслу).
2. **Ближайшее занятие:** текст-факт (`Ближайшее: ср 18:00`); тап → детали/редактирование. **Не** единственный primary всего экрана. Если нет — «Нет ближайших занятий».
3. **Неделя · обобщение (MVP):** **одна строка активности** за последние 7 дней, формат вроде  
   `3 тренировки · питание 5/7 · вес обновлён`  
   (состав сегментов — из доступных дневников/метрик; нет данных — «Пока мало данных»). Не отдельный дашборд и не 3–4 карточки метрик.
4. **Действия (равноправные плитки с подписями):**
   - Записать на занятие → create в расписании с этим клиентом  
   - Тренировки → назначения  
   - Питание → назначения / дневник  
   - Трекеры  
   - Прогресс  

**Не делать на входе:** два ряда табов (секция + подвкладка). Детали — после выбора плитки.

**Primary «бог-кнопка»:** не обязателен. Допустимо визуально чуть выделить «Записать на занятие» среди плиток, без скрытия остальных.

### Канон Client home (A5) · 2026-07-31

Согласовано с директором.

**Слои (сверху вниз):**

1. **Прогресс за неделю** — одна строка активности за 7 дней (как на Pro-сводке по духу).
2. **Ближайшее занятие** (если есть) — одна информационная строка; тап → детали. Если нет — блок не показывать (не empty-крик).
3. **Плитка «Прогресс»** (крупнее остальных) — основной вход на `workspace-measurements` (**не** таб нижней панели). Мини-график **веса**: при **≥3** точках — **последние 3**; иначе — без графика.
4. **Компактный ряд ключевых действий** (дублируют bottom tabs намеренно): **Тренировки · Питание · Трекеры**.

**Не на главной:** Поддержка, Профиль, полный дашборд виджетов, развёрнутый график.

Нижняя панель Client без изменений по составу: Главная · Тренировки · Питание · Трекеры.

### Словарь и виды · 2026-07-31

| Сущность | Имя | Не называть |
|----------|-----|-------------|
| Занятия / слоты тренера | **Расписание** | Календарь (как имя экрана) |
| Фиксация результатов клиентом (тренировки, питание, трекеры) | **Дневник** / **Дневники** | Календарь |

**Client · дневник (канон вида):**

1. Основной вид — **день**.
2. Сверху — **полоска дат текущей недели** (как уже в дневнике питания и трекерах; унифицировать везде).
3. Дата **без записей** — визуально приглушена («неактивная»), но **тапабельна**; в теле дня — спокойный empty: записей в этом дне нет.
4. Режимы неделя/месяц/agenda как равноправный сегмент toolbar — **не** для Client-дневников (упрощение виджета).

**Pro · Расписание (направление):**

- Цель: наглядная **сетка часов** — дни по X, часы по Y.
- Число колонок дней — **отзывчиво по ширине** (не фиксированные «только 3» или «только 5»):
  - узкий телефон → **3** дня;
  - шире (крупный телефон / маленький планшет) → **5**;
  - широкий / планшет → **7** (полная неделя).
- Сдвиг окна — стрелки / полоска; якорь «сегодня». Точные breakpoints — в wireframe среза 0 (ориентир: ~360 → 3, ~600 → 5, ~900+ → 7).
- **Ось часов (MVP):** видимый диапазон по умолчанию **07:00–22:00** (не полные 24 ч); вертикальный скролл внутри сетки. При открытии — скролл/якорь к **сегодня** и к **текущему часу** (или к ближайшему слоту, если «сейчас» вне диапазона).
- **«Мои часы» в профиле тренера:** тренер задаёт свой рабочий диапазон (начало–конец); сетка Расписания использует **его** часы вместо дефолта 07–22. Пока не задано — дефолт 07:00–22:00. (Срез внедрения: вместе с сеткой или сразу после; профиль уже в **Кабинете**.)
