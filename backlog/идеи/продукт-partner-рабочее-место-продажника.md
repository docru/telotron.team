## Суть

Сейчас ориентация сервиса — **на тренера**. Мысль: явно оформить **три продукта** под три аудитории:

| Продукт | Для кого | Сейчас |
|---------|----------|--------|
| **Pro** | Тренеры | Есть |
| **Client** | Клиенты тренеров | Есть |
| **Partner** | Партнёры — прежде всего **активные продажники** | Почти нет: в Pro — ссылки и статистика рефералов |

**Partner** — отдельное приложение/зона: удобное **рабочее место продажника**, который продаёт Telotron тренерам. Не «ещё одна ссылка в Pro», а продукт под цикл: нашёл → продал → довёл до оплаты → получил деньги → повторил.

Текущая партнёрка в Pro (L1/L2/L3 с topup) остаётся каноном начислений; Partner-продукт — **UX и инструменты продаж** поверх (и/или отдельная роль без обязательного «быть тренером»).

---

## Зачем / для кого

| Кто | Зачем |
|-----|--------|
| **Активный продажник** | Зарабатывать на продаже Telotron с понятными деньгами, воронкой и материалами |
| **Руководитель сети** | Видеть команду, споры по лидам, сводку (связь с [головным партнёром](головной-партнёр-атрибуция-и-продажа-компании.md)) |
| **Telotron** | Масштаб без своего отдела продаж; третий чёткий продукт в линейке |
| **Тренер-реферал** | Может остаться на лёгкой партнёрке в Pro; Partner — для тех, кто **продаёт системно** |

## Потребности продажника (что закрывать продуктом)

Чтобы продукт был привлекателен **активному** продажнику (не «тренер иногда кинул ссылку»):

### 1. Деньги — ясно и предсказуемо
- Сколько с одной продажи и **с какого события** (reg / activated / первая оплата / topup).
- Когда начислится и когда можно **вывести**.
- История выплат без «напишите в поддержку».
- Калькулятор: «N тренеров → вилка дохода».

### 2. Свои лиды и воронка (мини-CRM)
- Список ведомых тренеров и статусы (новый → созвон → триал → платит → отвал).
- Напоминания («не трогал 3 дня», «триал кончается»).
- Заметки после звонка.
- Свои лиды не смешиваются с чужими.

### 3. Материалы для продажи
- Питч 30 сек / 2 мин, возражения, one-pager, скрины.
- Шаблоны сообщений (MAX / TG / WhatsApp).
- Ссылка / QR / промокод **с его атрибуцией**.

### 4. Быстрый старт сделки
- Посадить тренера на reg за 1–2 минуты «при нём».
- Видно: зарегистрировался, зашёл, прошёл онбординг.

### 5. Контроль прогресса и качества
- Понятные правила: за что платят (лучше не «голый reg»).
- Живые статусы приглашённого; алерт «дожми до оплаты».

### 6. Обучение без тяжёлого курса
- Короткий онбординг: кому продаём / кому нет.
- Скрипт первого касания.
- Опционально цели/рейтинг (без MLM-шоу).

### 7. Команда и иерархия (если сеть)
- Свои L2/команда; правила «чей лид».
- Сводка для руководителя сети.

### 8. Доверие
- Прозрачная оферта; стабильные правила %; поддержка, если тренер застрял на входе; понятный вывод денег.

### 9. Мобильность
- Телефон first: статус, ссылка, заметка за ~20 секунд.
- Пуш по событиям «своего» тренера.

**Сигнал «хочу пользоваться»:** я зарабатываю · контролирую · мне помогают продавать · не кинут · сделка не тормозит.

## MVP (черновик scope)

| Входит | Не обязательно сначала |
|--------|-------------------------|
| Прозрачные деньги + история + калькулятор | Полный dialer / телефония |
| Воронка + статусы + напоминания + заметки | Замена Bitrix «на всё» |
| Материалы + персональная ссылка/QR | Сложная MLM-витрина пакетов |
| Статусы приглашённых в реальном времени | Раздача лидов от платформы «в подарок» |
| Мобильный UI Partner | Отдельный бренд «не Telotron» |

Ядро MVP: **деньги + воронка + материалы + статусы + вывод/история**.

## Отличие от партнёрки в Pro сейчас

| | **Partner в Pro (сейчас / MVP)** | **Продукт Partner (идея)** |
|--|----------------------------------|----------------------------|
| Персона | Тренер, иногда зовёт коллег | Продажник как основная роль |
| UX | Ссылки, приведённые, статистика, вывод | Рабочий стол продаж + CRM-лайт |
| Материалы | Почти нет | Питчи, скрипты, one-pager |
| Воронка | Слабо / статусы ограниченно | Полноценные этапы и дожим |
| Вход | Нужен аккаунт тренера | Отдельная зона / роль (TBD: без Pro-обязаловки) |

Начисления L1/L2/L3 и commerce — **не ломать** без DEC; меняется оболочка и, возможно, роль «partner-only».

## Гипотеза

Если дать активному продажнику **отдельный продукт** с прозрачным заработком, воронкой и оружием продаж, вырастет число тренеров с атрибуцией партнёров и стабильность выплат сети — без найма штатного отдела продаж Telotron.

**Как проверить:** 5–15 человек с ролью «продаю системно»; метрики — # сделок/мес на партнёра, время reg→paid, % дошедших до оплаты, NPS партнёра, факт выводов.

---

## Зависимости / когда брать

- Стабильные **Commerce + Partner начисления/вывод**.
- Зафиксированные правила «за что платим» (событие выплаты).
- Есть хотя бы небольшое ядро людей, которые **реально продают**, а не «когда-нибудь».
- Решение: Partner = **отдельное PWA** vs вкладка в Pro vs оба.

Иначе третий продукт станет красивой оболочкой над пустой партнёркой.

## Открытые вопросы

- [ ] Partner-only аккаунт **без** роли тренера — да / нет?
- [ ] Отдельный домен/PWA (`partner.telotron…`) или раздел в Pro?
- [ ] Событие выплаты для «продажника»: topup (как сейчас) / первая оплата / activated — что продаём в КП партнёру?

- [ ] Юр.: статус партнёра (самозанятый / ИП / договор), чеки при выводе.
- [ ] Не размыть фокус: три продукта vs один Pro с режимами.
