## Суть

Тренер **назначает клиенту задания** на **день**, **неделю** или **периодически** (каждый N-й день / по дням недели): что сделать и зафиксировать.

Типы заданий (черновик):

| Тип | Пример |
|-----|--------|
| **Трекер** | Выпить 2 л воды · отметить сон · пройти 8 000 шагов |
| **Упражнения** | Домашняя тренировка / разминка / конкретный комплекс из библиотеки |
| **КБЖУ / питание** | Уложиться в норму ккал/БЖУ · заполнить дневник · N приёмов пищи |
| **Свободное** | Текст: «фото прогресса», «растяжка 10 мин» (опц.) |

Клиент видит список на сегодня / неделю, отмечает выполнение, прогресс виден тренеру. Это слой **«что нужно сделать»**, а не только «что клиент сам решил залогировать».

---

## Зачем / для кого

| Кто | Зачем |
|-----|--------|
| **Тренер** | Дисциплина без ежедневного пинга в чате; единый чеклист по клиенту; видно, кто сливается |
| **Клиент** | Понятно, **что делать сегодня/на неделе**; меньше «а что от меня ждут?» |
| **Платформа** | Столпы **автоматизация + удержание** ([УТП](утп-и-картина-развития-продукта.md)); выше activation трекеров и питания |
| **PO** | Склейка уже существующих модулей (трекер / тренировки / питание) в один UX «задания» |

---

## Отличие от того, что уже есть

| Сейчас | Задания (эта идея) |
|--------|---------------------|
| Трекер: клиент **сам** пишет воду/сон/шаги | Тренер **требует** цель и видит done/not done |
| Программа тренировок: план занятий / выполнения | Задание может ссылаться на тренировку **или** быть разовым/привычкой вне полного плана |
| План питания / дневник | Задание: «веди дневник» / «цель КБЖУ на день» как чекбокс с привязкой к факту |
| Напоминания M4 | Пуш «сделай задание»; сами задания — отдельная сущность |

Не заменяет программы и трекеры — **оркеструет** их через назначения.

---

## Механика (черновик)

```text
Pro · карточка клиента / шаблоны заданий
  создать задание: тип · цель · период (день | неделя | cron/дни недели)
  назначить клиенту (или группе — TBD)
        ↓
Client · «Задания на сегодня» / «На неделю»
  список · прогресс · CTA в трекер / тренировку / дневник
        ↓
Факт (лог трекера / выполнение тренировки / КБЖУ за день)
  → авто-закрытие задания или ручная галка (по типу)
        ↓
Pro · выполнение % · пропуски · сигнал риска слива (связь с CRM-идеями)
```

| Период | Поведение |
|--------|-----------|
| **День** | Список на календарный день; сгорает / переносится — TBD |
| **Неделя** | Цель на неделю (напр. 3 тренировки, средние ккал) |
| **Периодически** | Повторять: пн/ср/пт · каждые 2 дня · «каждый день до даты» |

### Авто-закрытие vs ручная отметка

| Тип | Предпочтение |
|-----|--------------|
| Вода / шаги / сон | Авто по факту трекера ≥ цели |
| Тренировка | Авто по выполнению связанной тренировки |
| КБЖУ | Авто если дневник заполнен и/или сумма в коридоре цели |
| Свободный текст | Ручная галка клиента (+ опц. фото) |

---

## Гипотеза

Если клиент каждое утро видит **короткий список заданий от тренера**, растёт заполнение трекеров и дневника, падает «тишина» в сопровождении; тренер раньше видит пропуски.

**Как проверить:** 5–10 тренеров; D7 open rate заданий; % авто-закрытых; корреляция пропусков с churn; опрос «понятнее ли, что делать».

## Открытые вопросы

- [ ] Сущность: новый модуль **«Задания»** или флаги/цели поверх трекера и программ?
- [ ] Шаблоны заданий на уровне тренера (библиотека) vs только per-client?
- [ ] Групповое назначение (всем клиентам / сегменту)?
- [ ] Пропущенное задание: перенос на завтра, штрафной статус, или просто «missed»?
- [ ] КБЖУ-цель: жёсткий коридор или «заполни дневник» без проверки цифр (пока нет точного КБЖУ)?
- [ ] Тариф: Лайт / Профи / Макс?
- [ ] Связь со [статьями](учебные-материалы-библиотека-статей-тренера.md): задание «прочитай материал X»?
- [ ] Медицина: нормы КБЖУ как **цель тренера**, не мед. назначение — дисклеймер ([граница](ai-подсказки-тренеру-граница-медицины.md)).
