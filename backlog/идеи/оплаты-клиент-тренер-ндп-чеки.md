**Предлагаемый порядок:** ручная отметка «оплачено» (A2-min) → приём платежа в приложении → авточек НПД через API ФНС.

## Суть

Клиент платит тренеру **через Telotron** (занятие, абонемент). После успешной оплаты для **самозанятого** тренера система **автоматически** формирует чек НПД через интеграцию с **налог.ру / «Мой налог»** (партнёрский API) и **отправляет чек клиенту** — без ручного ввода каждого чека в приложении ФНС.

Снимает операционку: сейчас самозанятые вбивают каждый чек в «Мой налог» сами.

## Зачем / для кого

- **Тренер-самозанятый** — оплата + чек в одном контуре; меньше рутины и риска забыть чек.
- **Клиент** — прозрачная оплата и подтверждение (чек в приложении / на почту).
- **Telotron** — «клиент, план, отчёт, **оплата**» в одном месте (боль из интервью); сильный аргумент **Профи / Макс**.

## UX (канон идеи, целевое)

**Pro:** выставить счёт / ссылку на оплату; статус «ожидает / оплачено / просрочено»; история по клиенту.

**Client:** «Оплатить» (карта, СБП — через эквайринг); после успеха — чек и статус.

**Самозанятый:** один раз привязать «Мой налог» (OAuth / партнёрский контур); дальше чеки создаются автоматически при webhook «оплачено».

**Не все тренеры — НПД:** режимы `npd` (авточек) | `ip` | `manual` (только учёт оплаты без чека ФНС).

## Архитектура (черновик)

Два слоя — не смешивать:

```text
Слой 1 · Платёж
  Client → checkout (ЮKassa / аналог, split или выплата тренеру)
  → webhook «оплачено» → запись client_payment в БД

Слой 2 · Чек НПД (только npd + успешный платёж)
  → API ФНС / партнёр «Мой налог»: регистрация дохода, чек покупателю
  → клиенту: ссылка/PDF чека; тренеру: статус в Pro
```

**Не из браузера** — ключи эквайринга и ФНС только на сервере.

Оценка целого модуля: **~80–150 ч** (платежи, webhook, карточка, ФНС, UI Client+Pro, юр., тесты) — порядок **второго Commerce**.

## Этапы поставки (предлагаемые)

| Этап | Содержание |
|------|------------|
| **0** | Ручная отметка «оплачено» в карточке клиента (**L-20**, A2-min) |
| **1** | Счёт / ссылка на оплату, без авточека НПД |
| **2** | Успешный платёж → авточек НПД + доставка клиенту |
| **3** | Абонементы, напоминания о продлении (**L-21**) |

## Риски

| Риск | Митигация |
|------|-----------|
| Telotron как платёжный посредник | Юрист: роль платформы, 54-ФЗ, оферта тренер–клиент |
| Партнёрство с ФНС | Регистрация партнёра; не «API за день» |
| Ошибочный чек | Логи, отмена/корректировка по регламенту НПД |
| Не НПД (ИП, ООО, клуб) | Режимы без авточека |
| Split / комиссия платформы | Отдельное продуктовое решение; в глоссарии пока «не планируется» |
| Объём и срок | После **prod Commerce** и решения PO по **A2**; не блокер пилота 01.08 |

## Гипотеза

Если оплата занятия и чек НПД проходят в Telotron без «Мой налог» вручную, выше retention solo-тренеров и доля оплат через продукт vs перевод в мессенджер; проверка — % тренеров на НПД, NPS, объём платежей через приложение.
