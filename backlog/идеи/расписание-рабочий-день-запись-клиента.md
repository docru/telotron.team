## Суть

Сейчас тренер **создаёт отдельные занятия** в календаре, клиент записывается на уже опубликованные слоты (`scope=bookable`).

Предложение: тренер задаёт **расписание рабочего дня** — начало и конец + **перерывы**; клиент **сам выбирает** свободный интервал внутри рабочего времени (занятые окна недоступны).

## Зачем / для кого

- **Тренер** — не плодить занятия по одному; один раз настроил «когда я работаю».
- **Клиент** — видит реальную доступность, а не только заранее созданные слоты.

## Гипотеза

Если тренер задаёт рабочий день + перерывы, а клиент бронирует свободные окна — **меньше рутины у тренера** и **больше записей** без предварительного создания каждого занятия. Проверка: время на подготовку недели у тренера; % клиентов, записавшихся без сообщения «когда вам удобно».

## Черновик UX

**Pro**

1. Настройки / расписание: шаблон дня или по дням недели — **start / end**, список **перерывов**.
2. Календарь показывает занятость (уже записанные / созданные события) поверх рабочего времени.
3. Опционально: тренер по-прежнему может создать занятие вручную (гибрид на переходный период).

**Client**

1. Выбирает день → видит свободные интервалы внутри рабочего времени минус занятое.
2. Выбирает длительность (из настроек тренера / мин. длительность из канона M2) → подтверждает запись.
3. Создаётся `appointment` (+ `appointment_clients`) как сейчас после записи.

## Открытые вопросы

- [ ] Шаблон на все дни или разный график по дням недели?
- [ ] Длительность слота: фиксированная (30/45/60) или клиент выбирает из списка?
- [ ] Групповые занятия: остаются только как явные события или тоже из «окон»?
- [ ] Буфер между записями (например 10 мин)?
- [ ] Полный отказ от «создать занятие заранее» или гибрид?
- [ ] Связь с офлайн-слотами / TZ / лимитом отмены за N часов — без ломки текущего канона.
- [ ] Нужен ли approve тренера на самозапись или сразу `expected`?
