## Суть

При снижении баланса Ед. **ниже порога** (или перед ночным списанием, если не хватит на день) — **автоматически** списать с **привязанной карты** сумму пополнения (например, фиксированные 3000 ₽) и зачислить Ед. на внутренний счёт — без нажатия «Пополнить».

## Зачем / для кого

- **Тренер** — не уходить в Лайт из‑за забывчивости; меньше ручных действий.
- **Платформа** — стабильнее платный доступ при активных тренерах.

## Почему не в MVP (2026-07-08)

| Аспект | Комментарий |
|--------|-------------|
| **Scope** | [ADR-003](../../_telotron.ru/docs/Техдок/00-мета/архитектурные-решения/ADR-003-commerce-tovar-popolnenie-kupony.md): предоплата + nightly debit; карта только по кнопке |
| **Техника** | Сохранённая карта / рекуррент у ЮKassa, настройки порога и суммы, job, обработка отказов, идемпотентность, UI вкл/выкл — **отдельный слайс** (~15–25 ч) |
| **Юридика** | Явное согласие на автосписание, оферта, отключение в один клик, чеки 54-ФЗ — **с юристом** до prod |
| **Продукт** | Триал **без карты**; общий счёт с партнёрскими Ед. — нужны понятные правила «когда дёргаем карту» |

## Гипотеза

Если включить опциональное автопополнение, снизится доля непреднамеренных переходов в `light`/`frozen` без роста жалоб на «списали без меня» (метрика: % тренеров с автопополнением vs support-тикеты).

## Черновик scope (если созреет)

- Настройки: порог `balance < X`, сумма пополнения `Y` (≥ `min_topup_rub`), вкл/выкл.
- Триггер: cron после проверки баланса / перед `DailyDebitJob`.
- События: успех → как `topup` + `TopupSucceeded` для Partner; отказ → уведомление, без бесконечных повторов.
- Таблица/поля: например `commerce_auto_topup_settings` (префикс `commerce_`).

## Открытые вопросы

- [ ] Порог и сумма — фиксированные в конфиге или настраивает тренер?
- [ ] Триггер: «ниже порога» или «не хватит на завтрашний день»?
- [ ] Лимит попыток в сутки при отказе карты?
- [ ] ЮKassa: saved payment method vs отдельный recurring contract?
- [ ] Тексты согласия (юрист).
