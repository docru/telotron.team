## Суть

Общий UI-компонент для PWA: **записать** (или выбрать) короткое видео → **проиграть** → **обрезать** (без монтажа) → **отправить** в облако → **воспроизвести** позже.

Два продуктовых сценария (один компонент, разные привязки):

1. **Pro · конструктор** — тренер прикрепляет демо техники к упражнению; клиент смотрит при просмотре/выполнении тренировки.
2. **Client → Pro** — клиент снимает выполнение упражнения; тренер смотрит в отчёте по завершённому выполнению.

См. также общий контекст: [контент-коммуникации-обучение.md](контент-коммуникации-обучение.md) §1.

## Технический черновик (исследование)

| Этап | Подход | Заметки |
|------|--------|---------|
| Запись | `getUserMedia` + `MediaRecorder` → Blob в RAM | Разрешения камеры/микрофона; «переснять» |
| Канон файла | **MP4 / H.264 / AAC** | iOS часто пишет WebM → однократная конвертация после записи (`ffmpeg.wasm`) |
| Обрезка | На **клиенте**, до ~1 мин | `ffmpeg.wasm`; `-c copy` быстро, грубо по точности; для точности — `ultrafast` перекодирование |
| Размер | Ориентир **720p**, ~15–30 МБ/мин | Лимит длительности (напр. 60 с) и размера на API |
| Загрузка | **Pre-signed PUT** в Yandex Object Storage | Мимо тела приложения; CORS на бакете |
| Метаданные | Сервер выдаёт Key → клиент грузит → callback «загрузка завершена» | На старте — от клиента; позже — S3 Events |
| Просмотр | Отдельная **pre-signed GET**, короткий TTL | Права: тренер / клиент по binding |
| Надёжность | Очередь upload в IndexedDB | Background Sync в Safari слабый |
| WASM | Нужны **COOP/COEP** для `ffmpeg.wasm` | Проверить влияние на остальной PWA |

**Не в scope идеи:** монтаж, несколько клипов, субтитры, публичный бакет.
