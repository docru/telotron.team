## Суть

Тренер ведёт **свою библиотеку учебных материалов** (статьи: питание, техника, восстановление, правила, FAQ). В **чате с клиентом** может **присоединять ссылку на статью** из библиотеки — клиент открывает материал внутри Client, без PDF и «потерянных» ссылок в мессенджере.

Материалы живут у тренера как актив: один раз написал → многократно отправляет разным клиентам.

---

## Зачем / для кого

| Кто | Зачем |
|-----|--------|
| **Тренер** | Не повторять одни и те же объяснения в чате; база знаний под бренд; меньше усилий на сопровождение |
| **Клиент** | Читает в том же приложении, где план и прогресс; материалы не теряются в переписке |
| **Платформа** | Усиливает столп «прозрачность / удалёнка» ([УТП](утп-и-картина-развития-продукта.md)); аргумент «всё в одном» vs TG |
| **PO** | Контент-слой проще курсов: статьи → позже упаковка в [курсы](курсы-для-клиентов-продажа-через-тренера.md) |

## Механика (черновик)

```text
Pro: библиотека статей тренера
  создать / править / теги / черновик|опубликовано
        ↓
Чат с клиентом → «Прикрепить статью» → выбор из библиотеки
        ↓
В сообщении — карточка/ссылка на статью
        ↓
Client: открытие статьи (read), история «материалы от тренера»
```

| Элемент | Описание |
|---------|----------|
| **Библиотека** | Список статей тренера: заголовок, тело, обложка (опц.), теги, статус |
| **Редактор** | Markdown или простой WYSIWYG (TBD) |
| **Шаринг в чате** | Deep link / вложение-карточка: превью + переход в статью |
| **Доступ** | Только клиенты этого тренера (private по умолчанию) |
| **Повторное использование** | Одна статья → много клиентов / много раз в переписке |

### Что не входит в MVP идеи

- Публичный SEO-маркетплейс статей (это ближе к [курсам / витрине](курсы-для-клиентов-продажа-через-тренера.md)).
- Обязательная модерация каждой статьи платформой (кроме жалоб / мед. красных линий).
- Полноценная LMS (тесты, сертификаты) — это курсы.

## Зависимости

| Блокер | Зачем |
|--------|--------|
| **Чат тренер ↔ клиент (M3)** | Без чата «прикрепить в переписке» некуда; можно временно «отправить в ленту материалов», но канон — чат |
| **Client UI статьи** | Просмотр, безопасный HTML/Markdown |
| **Хранение** | Текст в БД; картинки — S3/CDN при необходимости |
| **Юр. / ПДн** | Мед. советы в статьях — граница ([AI / Минздрав](ai-подсказки-тренеру-граница-медицины.md)); дисклеймер в редакторе |

## Гипотеза

Если тренер копит библиотеку и **в 1 клик кидает статью в чат**, падает объём однотипных текстовых ответов, растёт perceived value Client («материалы под рукой»), выше retention у клиентов с ≥1 открытой статьёй.

**Как проверить:** пилот 5–10 тренеров после чата; метрики — # статей в библиотеке, # отправок в чат, open rate, повторные открытия, опрос «удобнее, чем PDF/TG».

## Открытые вопросы

- [ ] Только свои статьи или ещё **каталог шаблонов** от Telotron (скопировать → править)?
- [ ] Клиент видит **всю библиотеку** тренера или только то, что ему отправили?
- [ ] Можно ли прикреплять статью **не только в чате** (карточка клиента, программа, напоминание)?
- [ ] Версионирование: правка статьи после отправки — клиент видит новую версию?
- [ ] Тариф: библиотека на Лайт / Профи / Макс?
- [ ] Лимиты: размер, число статей, вложения-картинки.
- [ ] Позже: публичные статьи тренера на лендинге / SEO — отдельный DEC (не смешивать с private-библиотекой).
