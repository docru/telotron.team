## Суть

У **тренера (Pro)** и **клиента (Client)** на **главной** — набор **виджетов** (состав, порядок, параметры). Есть **общая начальная настройка** (дефолт layout) для новых пользователей / по роли / по тарифу.

**Настройка пунктов главного меню** — **не** в этом файле: [главное-меню-настраиваемые-пункты](главное-меню-настраиваемые-пункты.md). В **T-097 v1** — только виджеты.

---

## Зачем / для кого

- Тренер: «сразу своё» — записи, клиенты в риске, финансы — без перегруза.
- Клиент: прогресс, ближайшие занятия, оповещения.
- Продукт: один механизм персонализации home вместо жёсткой вёрстки.

---

## Виджеты на главной

### Примеры

| Виджет | Зона (черновик) | Смысл |
|--------|-----------------|--------|
| Блок иконок-ссылок на основные разделы | Pro + Client | Карта продукта |
| Ближайшие записи | Pro + Client | Календарь / ближайшее |
| Последние оповещения | Pro + Client | Лента напоминаний / событий |
| Главная информация по клиентам | **Pro** | Список / риск / KPI |
| Основная финансовая информация | **Pro** | Учёт / к оплате / доход |
| Мой прогресс | **Client** | Вес, стрик, факт тренировок |

### Правила (черновик)

- Пользователь: состав, порядок, параметры (фильтры, период, размер…).
- Параметры валидируются по `type` (whitelist).
- Сброс к дефолту.

---

## Гипотеза

Если home конфигурируема с дефолтом «из коробки», выше ощущение «всё нужное сразу видно»; проще A/B дефолтов без форка UI.

---

## Набросок модели (не ТЗ)

```text
shell_prefs (user_id, zone: pro|client)
  home: ordered widgets[{ type, params, visible }]

default_shell (zone, tariff?, segment?)
```
