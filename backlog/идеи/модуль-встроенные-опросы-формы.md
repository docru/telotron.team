## Суть

Встроенный в PWA **модуль опросов** (аналог Google Forms) для зон **Pro** и **Client**: админка создаёт формы, назначает аудитории, пользователь видит предложение пройти опрос в приложении, ответы сохраняются в БД и выгружаются для анализа.

**Цель:** регулярно собирать обратную связь для **повышения качества продукта** и **маркетинговых/продуктовых решений**, не уводя пользователей во внешние формы.

**Мотивация тренера:** за прохождение опроса — **начисление баллов на счёт** (зачёт в партнёрском/коммерческом контуре — уточнить).  
**Мотивация клиента:** **TBD** — отдельно продумать.

## Зачем / для кого

| Кто | Зачем |
|-----|--------|
| **Продукт / PO** | Регулярный NPS/CSAT, проверка гипотез, insight без Google Forms |
| **Маркетинг** | Опросы пилота, сегменты, кастомные кампании |
| **Тренер** | Участие в улучшении сервиса + **вознаграждение** за время |
| **Клиент** | Голос в развитии продукта (стимул — позже) |
| **Админ** | Конструктор, назначение, выгрузка ответов |

Связь с контуром валидации: [Соответствие продукта запросам пользователей](../../../02-Маркетолог/Инструкции/Соответствие%20продукта%20запросам%20пользователей%20—%20контур%20валидации.md), [insight-brief](../insight-brief/) (evidence из опросов).

## Отличие от M14 (обратная связь)

| | **M14 (сейчас)** | **Модуль опросов (идея)** |
|--|------------------|---------------------------|
| Назначение | Обращение в поддержку, диалог | Структурированный опрос / анкета |
| Поля | Свободный текст | Типизированные поля, страницы |
| Создание | Пользователь | **Админ** (Filament) |
| Аналитика | Тикеты в админке | Агрегация, экспорт, SQL |
| Мотивация | Нет | Баллы тренеру (идея) |

Возможная эволюция: общий движок «форм» с разными `purpose` (`support` vs `survey`) — **ADR при реализации**.

## Функциональность (черновик)

### Пользователь (Pro + Client)

- [ ] При входе / в отдельном разделе — **предложение пройти активный опрос** (баннер, карточка, одноразовый лайтбокс — TBD).
- [ ] **Многостраничная форма** с прогрессом (шаг N из M).
- [ ] После отправки — подтверждение; для тренера — сообщение о **начислении баллов**.
- [ ] Один пользователь — **один ответ на опрос** (или разрешить повтор — настройка в админке).

### Типы полей (MVP опросов)

| Тип | Описание |
|-----|----------|
| `text` | Однострочный текст |
| `textarea` | Многострочный текст |
| `radio` | Один выбор из списка |
| `checkbox` | Несколько выборов из списка |

**Позже:** шкала 1–5, дата, загрузка файла, условная видимость страниц.

### Админка (Filament / platform admin)

- [ ] **Конструктор опроса:** название, описание, страницы, поля, обязательность.
- [ ] **Публикация:** черновик → активен → закрыт.
- [ ] **Назначение аудитории (этапы):**
  - **v1:** все пользователи зоны (Pro / Client / обе) или все зарегистрированные;
  - **v2:** категории (тариф, город, когорта пилота, дата регистрации, активность — TBD).
- [ ] **Награда тренеру:** сумма баллов за полное прохождение (0 = без награды).
- [ ] **Результаты:** просмотр в админке, **выгрузка** (CSV/Excel) или выборка из БД / read-only отчёт.

### Интеграция с «счётом» тренера

За прохождение опроса тренер получает **баллы на счёт** (формулировка директора: «деньги на счёт» — трактовать как **зачёт в партнёрском/абонентском контуре**, не прямой рублёвый перевод без юр. схемы).

**Открыто:** связь с [модуль-партнерка](../../../_telotron.ru/docs/Бизнес-требования/02-модули/partner/модуль-партнерка.md), Commerce, лимиты и налогообложение.

## Мотивация

| Роль | Статус |
|------|--------|
| **Тренер** | **Баллы на счёт** за завершённый опрос (размер задаётся в админке на опрос) |
| **Клиент** | **Не определено** — варианты на обдумывание: без награды; скидка на абонемент тренера (вне платформы); ранний доступ к фиче; благодарность без денег; геймификация |

## Маркетинговый контур

- Замена / дополнение **Google Forms** для пилотных и продуктовых опросов ([Baseline — анкета](../../../03-Разработчик/Исследования/Интервью/Baseline%20—%20анкета%20и%20мотивация%20для%20участия.md)).
- Таргетированные кампании: «опрос после 30 дней на платформе», «опрос после первого клиента».
- Согласованность с CRM пилота: не дублировать [входную/выходную анкету](../../../02-Маркетолог/CRM/Анкета%20—%20входная%20перед%20пилотом.md) без явного разделения целей.

## Гипотеза

Если опросы **внутри приложения** с **наградой тренеру**, доля завершённых анкет вырастет vs внешняя ссылка; продукт получит **ежемесячный поток структурированной ОС** без потери контекста (роль, тариф, версия app). Метрики: % completion, время до ответа, корреляция с retention.

## Риски

- **ПДн в ответах** — политика хранения, согласие, не логировать лишнее в audit.
- **Злоупотребление наградами** — мультиаккаунты, «прокликивание»; лимиты, один ответ на user_id.
- **Усталость от опросов** — частота, dismiss, не блокировать кабинет.
- **Юрист:** текст согласия на обработку ответов опроса; баллы как вознаграждение.
