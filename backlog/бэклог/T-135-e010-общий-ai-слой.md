## Контекст

Клиент Caila живёт в `Modules/Nutrition` и не умеет tools / `json_schema` / учёт стоимости. Для ИИ-консультанта нужен общий слой; второй копии клиента не делаем. Канон — ADR-010.

## Часть A · слой (не ждёт проб)

- [ ] `app/Modules/Ai`: `AiChatClient` (`chat`, `chatParallel`), `AiChatRequest`, `AiChatResult` по ADR-010 §2
- [ ] Шлюз `adapters/openai-direct`, полный model id; `config/ai.php` (`CAILA_API_KEY`, `CAILA_DIRECT_BASE_URL`, `enabled`, таймаут, необязательный `base_url` на модель)
- [ ] `responseFormat`: `text` · `json_object` · `json_schema`; `tools` / `toolChoice` → `toolCalls` в ответе (без цикла исполнения)
- [ ] `usage`: токены + `cost_rub`, если Caila отдаёт
- [ ] Таблица `ai_runs` (ADR-010 §4); запись на каждый вызов; ключ API — никогда в журнал и `Log`
- [ ] Команда по расписанию: через 30 дней обнулить `request_masked` / `response_masked`, через 1 год удалить строки
- [ ] `ai.enabled=false` → `error=disabled` без HTTP
- [ ] Ретраев по умолчанию нет; опция «1 повтор на timeout/5xx» в запросе
- [ ] Feature/Unit-тесты на `Http::fake`: успех, JSON schema, tool calls, таймаут, http-ошибка, disabled, запись `ai_runs`, очистка по сроку

## Часть B · перенос питания (после проб шлюза)

- [x] LLM-инженер подтвердил на `openai-direct`: `json_object`, `json_schema`, 3 модели КБЖУ, `usage.cost` — [отчёт T-138 §2](../../11-AI-инженер/Работа/e-010-brief-prompt-v1-eval.md)
- [ ] qwen: в запросе `reasoning: {"enabled": false}`, без `response_format` (иначе рассуждения в ответе или мусор) — нужен необязательный `extra_body` на модель в `config/ai.php` (согласовать с архитектором, дополнение ADR-010)
- [ ] gpt-4o-mini: Caila не отдаёт `usage.cost` → `cost_rub` по токенам × прайс или `null`
- [ ] `NutritionAiEnsembleService` → `AiChatClient::chatParallel`, `scenario=nutrition.kbju_estimate`
- [ ] `NUTRITION_AI_MODELS` → полные id; модель, не работающая на `openai-direct`, — через `base_url` в конфиге (ансамбль не меняем)

- [ ] Техдок: схема питания (ссылка на ADR-010 вместо клиента Caila)
