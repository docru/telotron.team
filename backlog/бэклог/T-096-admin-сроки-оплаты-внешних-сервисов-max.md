## Контекст

Нужны **оповещения админу в MAX по ключевым операционным рискам**. **Первый приоритет** — **истечение сроков оплаты / продления внешних сервисов**, без которых падает prod (облако, домен, OTP, почта, мессенджеры, эквайринг).

### Похожие задачи

| Тикет | Что уже есть | Отличие |
|-------|--------------|---------|
| **[T-095](T-095-admin-оповещения-max.md)** | Подписка staff на MAX + `AdminNotificationService` + реестр **продуктовых** событий (регистрация тренера, feedback, webhook оплаты…) | T-095 — **канал и платформа**. T-096 — **реестр платных сервисов** и cron-напоминания «скоро срок / просрочено» |
| [T-074](T-074-заключить-договор-sms-aero.md) | Договор SMS Aero | Юр/ops по одному провайдеру, не общий календарь |
| [T-035](T-035-commerce-напоминания-триала.md) | Напоминания **тренеру** о конце триала | Пользовательский Reminder, не admin ops |

**Зависимость:** доставка в MAX — через сервис из **T-095** (или минимальный MVP-отправитель в том же тикете, если T-095 ещё не взят). Не дублировать bind MAX.

## Scope тикета

### 1. Реестр сервисов в продукте (Filament или config + admin UI)

- [ ] Сущность вроде `ops_vendor_services` (или таблица в Filament): название, URL кабинета, дата следующей оплаты / окончания баланса, горизонт напоминаний (например **30 / 14 / 7 / 1** день), контакт владельца, критичность (`critical` / `normal`).
- [ ] Первичное заполнение строками из раздела **«Список сервисов»** выше (хотя бы A+B+C с известными датами).
- [ ] Ручное обновление даты после оплаты (пока без автосинхронизации с кабинетами провайдеров).

### 2. Напоминания в MAX

- [ ] Scheduler (cron): раз в сутки МСК проверять сервисы → события `ops.vendor_renewal_due` / `ops.vendor_overdue`.
- [ ] Доставка через **T-095** `AdminNotificationService` (или временный тонкий sender, если T-095 позже).
- [ ] Идемпотентность: не слать один и тот же горизонт дважды за день/эпизод.
- [ ] Тестовая кнопка «Проверить напоминания» в админке.

### 3. Документация

- [ ] Канон: короткий техдок или раздел в runbook «Реестр внешних сервисов и алерты».
- [ ] Связь с T-095: событие `ops.vendor_*` в реестре admin-событий.

## Критерии готовности (v1)

- [ ] В админке виден реестр ≥ сервисов из блоков **A–C** (даже с пустыми датами).
- [ ] Для ≥ 1 тестового сервиса с датой — приходит сообщение в MAX за N дней (N из конфига).
- [ ] Feature-тест: фиксация «сегодня» → событие due → вызов notifier (mock MAX).
- [ ] Runbook: куда смотреть после оплаты, как сдвинуть дату.

## Вне scope v1

- Автоподтягивание баланса/дат из API Яндекс Облака, REG.RU, Voice Password и т.д.
- Продуктовые события Commerce/Feedback (это T-095).
- Напоминания тренерам о триале (T-035).
- Uptime / PagerDuty.
