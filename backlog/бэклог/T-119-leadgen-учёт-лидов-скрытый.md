## Контекст

Учёт людей и этапов **внутри системы** — тренер видит **задачи**, не «воронку».  
Лиды: со страницы записи, из базы (пробная), вручную. Переход **лид → Client / запись** в M2.

## Критерии готовности

- [ ] Модель **Lead:** источник (лендинг, база, вручную, utm), контакт, статус, связь с ReactivationContact при реактивации
- [ ] Статусы цепочки: заявка → контакт → пробная → оплата / отказ (упрощённо)
- [ ] Pro UI: **список заявок** (не CRM-board); карточка; смена статуса из задач дня
- [ ] **Стык M1/M2:** кнопка «принять как клиента» / «записать на пробную» → invite или booking API
- [ ] Сводка для совещения: счётчики за неделю
- [ ] Тесты: лид с лендинга, merge с базой, переход в Client

## Вне scope

- Риск слива, scoring ([идея](../идеи/crm-индикатор-риска-слива.md)) — P2
- Kanban / воронка на виду
