## Контекст

Тренер пилота каждое утро получает 1–3 задачи на сегодня с «зачем». Код готовит кандидатов, ИИ выбирает и объясняет; при сбое — бриф по правилам. Канон — ADR-011.

## Критерии готовности

### Сигналы CRM → задачи
- [x] Три сигнала (ADR-011 §2): новый контакт без касаний; следующее действие сегодня/просрочено; «в работе» > 7 дней без касания (порог в конфиге)
- [x] Слушатели событий CRM + ежедневный проход по крону; дедупликация `(контакт, тип сигнала)`
- [x] CRM читается через сервисы `Modules/Crm`; в CRM ничего не пишем

### Расчёт
- [x] Кандидаты: открытые задачи на сегодня и просроченные (до 15) + цифры воронки + до 10 людей под макросами `{{name_N}}` (только люди из переданных кандидатов); вход — по [контракту T-138 §4.1](../../11-AI-инженер/Работа/e-010-brief-prompt-v1-eval.md)
- [x] Подготовка кандидатов до вызова ИИ ([T-138 §4.2](../../11-AI-инженер/Работа/e-010-brief-prompt-v1-eval.md)): сортировка по типу и просрочке + отсечение нижних уровней приоритета; тот же порядок — в брифе по правилам; 0 кандидатов → без вызова ИИ
- [x] Вызов `Modules/Ai`: `scenario=leadgen.morning_brief`, `json_schema`, модель и версия промпта из конфига. Промпт и схема — файлы из [T-138](../../11-AI-инженер/Работа/e-010-brief-eval/prompt/); конфиг: `gpt-4o-mini`, temperature 0.2, max_tokens 400, таймаут 15 с, `why` ≤160
- [x] Проверка ответа (ADR-011 §3) → иначе бриф по правилам, `source=rules`
- [x] Маскирование: телефон / ник / канал / полное имя в LLM не уходят; подстановка имён после ответа
- [x] Профиль не заполнен → одна задача «Заполните профиль», без вызова ИИ

### Хранение, свежесть, крон, лимиты
- [x] Таблица брифов: тренер + локальная дата (уникально), пункты, `source`, `ai_run_id`, «устарел», время, счётчик ручных обновлений
- [x] Отметка «устарел» по изменению задач и событиям CRM (новый контакт, смена этапа)
- [x] Крон каждые 15 минут: `leadgen.brief_hour` (07:00) по часовому поясу тренера → job
- [x] Лимит: 1 крон + 5 ручных «обновить» за локальные сутки; сверх — понятный отказ

### Доступ и API
- [x] Галочка «пилот LeadGen» у тренера в Filament; флаг в ответе `/api/v1/me` (или features)
- [x] `GET /api/v1/me/leadgen/brief`: нет брифа → синхронный расчёт; устарел → старый + `refreshing`, job в очередь; свежий → как есть
- [x] `POST /api/v1/me/leadgen/brief/refresh` (лимит)
- [x] Вне белого списка — 403

### Тесты (моки `Modules/Ai`)
- [x] Сигналы и дедупликация; выбор только из кандидатов; невалидный ответ → правила; сбой провайдера → правила
- [x] В запросе к ИИ нет телефона и ника; подстановка имён
- [ ] Перед prod: LLM-инженер прогоняет [проверочный набор T-138](../../11-AI-инженер/Работа/e-010-brief-eval/golden-set-v1.json) через код T-136 на stage и сверяет с отчётом
- [x] Крон по часовому поясу; лимит обновлений; «устарел» → `refreshing`; профиль не заполнен; 403 вне пилота

### Документация
- [x] Техдок модуля LeadGen (схема данных, API) со ссылкой на ADR-011

### 2026-10-02 (уточнение · блок A)

- «Касание» для сигналов = действие тренера (заметка, смена этапа, следующее действие, «сделано» по задаче сигнала); касание от заявки лида не считается.
- Цифры воронки: новые · в работе; `trials: null` (контракт промпта v1 не меняем); новые клиенты за 7 дней — с промптом v2.
- TZ тренера: Pro шлёт пояс устройства при открытии → `users.timezone`; нет — `Europe/Moscow`.

### 2026-10-01 (T-138 закрыт)

- LLM-инженер: промпт v1 + набор готовы ([отчёт](../../11-AI-инженер/Работа/e-010-brief-prompt-v1-eval.md)). Добавлены требования: подготовка кандидатов (сортировка + отсечение уровней), значения конфига, повторный прогон набора на stage.
- Отклонение от ADR-011 на решение архитектора: в `why` имён нет (пример «для {{name_1}}» даёт неверные склонения). Валидный макрос в `why` бриф не ломает — проверка ADR-011 §3 остаётся как есть.
