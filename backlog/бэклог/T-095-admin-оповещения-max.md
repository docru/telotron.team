## Контекст

Оператору нужны **оперативные сигналы** о событиях платформы вне постоянного мониторинга Filament. Канал доставки MVP — **MAX** (уже есть интеграция бота Pro/Client: `MaxBotApi`, webhooks, bind пользователей).

**Задача (черновик PO):**

1. В **админке** — настройка **подписки** оператора на канал оповещений в MAX (привязка / подписка на «канал тренера» в MAX — детали уточнить при старте).
2. **Сервис** отправки оповещений админу(ам).
3. **Реестр событий**, по которым шлём оповещение (первая версия списка — ниже; финальный — перед реализацией).

**Первый потребитель канала (продуктовый приоритет директора):** напоминания о **сроках оплаты внешних сервисов** — отдельный тикет **[T-096](T-096-admin-сроки-оплаты-внешних-сервисов-max.md)** (реестр вендоров + cron). T-095 даёт **доставку**; T-096 — **календарь оплат**.

**Не путать** с модулем **Reminders** (клиент/тренер, занятия, триал) и с **in-app** уведомлениями PWA — это **staff / ops** контур.

## Scope (черновик, уточнить при старте)

### 1. Админка (Filament)

- [ ] Раздел/настройки **«Оповещения MAX»** (или в профиле staff): подключение MAX для получения ops-сообщений.
- [ ] Статус: привязан / не привязан; тестовое сообщение «Проверка».
- [ ] Хранение привязки **без сырых секретов** (аналог `max_chat_id` / token провайдера — по аналогии с пользовательским bind).
- [ ] Права: только `admin` / `super-admin` (guard `admin`).

*Открыто:* это **личная** привязка каждого оператора или **один** общий MAX-чат/канал на компанию?

### 2. Сервис оповещения админа

- [ ] Модуль/сервис, напр. `AdminNotificationService` (каталог на усмотрение: `app/Modules/Admin/` или `Integrations/`).
- [ ] Единая точка: `notify(AdminNotificationEvent $event)` → форматирование текста → отправка в MAX.
- [ ] Идемпотентность / дедуп там, где нужно (повтор webhook, cron).
- [ ] Ошибки доставки — **log** + опционально запись в `audit_events`; **не** блокировать бизнес-транзакцию.
- [ ] Конфиг: вкл/выкл канал MAX, env для prod/stage.

- [ ] `AdminNotificationService` отправляет сообщение в MAX.
- [ ] Зафиксирован **канонический список** событий v1 в техдоке (≥ 3 события, согласовано с PO).
- [ ] ≥ 3 события реально подключены к сервису (какие — по согласованному списку).

## Вне scope (пока)

- Telegram / e-mail для admin ops (только MAX в v1).
- Push PWA для операторов.
- Редактор шаблонов в UI (достаточно кода + техдок).
- Эскалации, on-call ротация, PagerDuty.
