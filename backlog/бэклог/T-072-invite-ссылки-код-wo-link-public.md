## Контекст

Решение [T-066 § тех. Q&A #1](T-066-упрощение-входа-эпик.md): тренер может зарегистрироваться **без** партнёрской ссылки в локальном хранилище браузера. Привязка к партнёру — через записи `invite_tokens` в БД.

Сейчас системные ссылки (платформенный «прямой вход», ссылка с публичного сайта) ищутся **по названию** (`title` в конфиге). Нужно поле **код** у ссылки и поиск **по коду**.

### Коды v1 (канон)

| Код | Смысл |
|-----|--------|
| `public` | Ссылка для перехода **с публичного сайта** (`/i/{код}` → токен в браузере); атрибуция **стандартная**, как у любой партнёрской ссылки |
| `wo_link` | Fallback при `register/complete`, если **нет** токена в браузере — прямой заход на страницу телефона |

Коды перечислены в **конфиге** приложения; в БД у соответствующих активных ссылок — то же значение в поле `link_code`.

## Технические требования

### Схема БД

- [ ] Колонка `invite_tokens.link_code` — `VARCHAR`, **nullable**, уникальная среди **активных** ссылок (или глобально unique nullable — зафиксировать в миграции).
- [ ] **Одноразовая миграция данных:** проставить коды существующим платформенным ссылкам:

  - ссылка «С сайта telotron» (`TelotronWebsiteInviteSeeder`) → `public`.
- [ ] Конфиг: `config/telotron.php` — массив или константы кодов системных ссылок.

### Код

- [ ] `register/complete` (T-068): токен в браузере → **как сейчас**. Нет токена → ссылка по коду **`wo_link`** из конфига ([T-066](T-066-упрощение-входа-эпик.md) Q&A #15). Код `public` — только метка ссылки в БД для сайта, не поле API.
