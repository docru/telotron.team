## Контекст

Сейчас shell жёсткий: у Client главная = трекеры (`ClientTrackerHomePage`); у Pro «домашняя» точка — расписание. Нет персонализации **главной**.

**Цель v1:** настраиваемый набор **виджетов** на главной (состав, порядок, параметры) + **дефолт layout** «из коробки».

**Pro (Q7):** ввести отдельный маршрут/пункт **«Главная»** с виджетами; **расписание** не заменяется — остаётся в меню как сейчас.

Принцип: **виджеты важного + ссылки на основное + редкое глубже**.

**Не в этом тикете:** настройка пунктов нижнего меню — идея [главное-меню-настраиваемые-пункты](../идеи/главное-меню-настраиваемые-пункты.md).

### Виджеты **MVP v1** (после Q3 + Q9)

| Код | Виджет | Зона |
|-----|--------|------|
| A | Иконки-ссылки на разделы | Pro + Client |
| B | Ближайшие записи | Pro + Client |
| C | Последние оповещения | Pro + Client |
| G | Трекер: **вода** | Client |
| H | Трекер: **шаги** | Client |
| I | Трекер: **сон** | Client |
| J | Быстрые действия: **Питание** + **Тренировка** | Client |

**Не в v1 (примеры на потом):** D сводка по клиентам, E финансы, F прогресс.

G–I — разбиение текущего блока ввода на главной (`ClientTrackerHomePage` / `ClientTrackerDayEditor`) на отдельные виджеты; поведение ввода как сейчас (в т.ч. день «сегодня» на главной).

**B / C (Q12 + Q15):** одна строка-превью + «Открыть все» → полный раздел. Если данных нет — виджет **не рисуется** на главной, но в настройках остаётся включённым.

**C + Pro (Q16 + Q17):** inbox у Pro **нужно сделать** (UI + «Открыть все» для виджета C). Контент v1 — **только уже существующие** in-app источники для Pro (то, что продукт уже умеет отдавать тренеру). **Новые типы** оповещений Pro — вне T-097. Если для Pro сейчас нет непрочитанных — виджет C скрыт (Q15).

### Дефолт layout (Q4 + Q9 + Q11)

| Зона | Порядок включённых по умолчанию | В каталоге (выкл.) |
|------|----------------------------------|--------------------|
| **Client** | G → H → I → **J** → B | A, C |
| **Pro** | B → A | C |

### Хранение (Q5)

```text
localStorage (per zone / user hint):
  home: widgets[{ type, params, visible }]

default_shell (code/config by zone)   // общая начальная настройка
```

Серверного API prefs в v1 **нет**.

## Канон: интерфейс, унификация, требования к виджетам

Полный текст: [`_telotron.ru/docs/Техдок/01-канон-mvp/frontend-home-виджеты-главной-mvp.md`](../../../_telotron.ru/docs/Техдок/01-канон-mvp/frontend-home-виджеты-главной-mvp.md) (также из [frontend-архитектура §6](../../../_telotron.ru/docs/Техдок/01-канон-mvp/frontend-архитектура-и-стек-mvp.md)).

### Именование и слои

- Папка `resources/ts/widgets/` = **shell-композиции**, не карточки главной.
- Home-виджеты: `HomeWidget*` · `shared/home-widgets/` (types, catalog, prefs, composable) · `widgets/home/` (Host, Editor, карточки).
- Pages — тонкие: greeting + host + «Изменить главную».

### Идентификаторы

| `HomeWidgetId` | PO | Зоны |
|----------------|----|------|
| `nav_links` | A | Pro + Client |
| `next_appointment` | B | Pro + Client |
| `notifications` | C | Pro + Client |
| `tracker_water` | G | Client |
| `tracker_steps` | H | Client |
| `tracker_sleep` | I | Client |
| `quick_actions` | J | Client |

В `localStorage` и TS — только `HomeWidgetId`; коды A–J — для PO/доков.

### Prefs

- Ключ: `telotron.home.layout.v1.${zone}` (+ опционально user hint).
- Форма: `{ version: 1, widgets: [{ id, enabled, params? }] }`.
- API: `read` / `write` / `default` / `resolve` (merge неизвестных/новых) / `reset`.
- Серверного API prefs в v1 нет.

### Runtime

Единые props карточки: `zone`, `params`, `reportEmpty(empty)` — для `emptyPolicy: 'hide_when_empty'` (B, C). Остальные — `always`.

### Унификация (обязательно)

1. Один Host + один Editor на обе зоны.
2. A — только из `proBottomTabs` / `clientBottomTabs` (+ Ещё).
3. B/C — одно превью + «Открыть все»; без мутаций на главной; пустые скрыть на home, `enabled` сохранить.
4. G–I — день «сегодня», логика трекера без копипаста.
5. J — Питание + Тренировка.
6. C Pro — inbox UI на **существующих** in-app источниках; без новых kinds.
7. Ошибка карточки не валит главную; тяжёлое — lazy.
8. Вне каталога (напр. IncompleteWorkout) — не смешивать с A–J без решения PO.

### DoD карточки

В registry; принимает runtime props; не пишет prefs сама; `reportEmpty` при необходимости; unit/smoke prefs + empty B/C.

### Shell (следствие)

Pro tabs: Главная · Расписание · Клиенты · Ещё; `shellHomeRouteName` → `workspace-home`. Сброс layout — с confirm.

## Scope реализации

- [x] v1: **только виджеты** главной (меню вне scope)
- [x] v1: зоны **Pro и Client**
- [x] MVP-виджеты: **A, B, C, G, H, I, J** (D/E/F — вне v1)
- [x] Дефолт layout: Client **G→H→I→J→B** (A и C выкл. в каталоге); Pro **B→A**; C выкл. в каталоге
- [x] Хранение prefs: **localStorage** (без серверного API в v1)
- [x] UI: кнопка **«Изменить главную»** на home → шит/экран (вкл/выкл + порядок)
- [x] Pro: новый пункт/маршрут **«Главная»** (виджеты); расписание отдельно
- [x] Лимит включённых виджетов: **нет**
- [x] Виджет A: ссылки = пункты **нижнего меню** зоны (+ «Ещё» при необходимости)
- [x] Client виджет **J**: быстрые действия Питание + Тренировка (не убирать с продукта — вынести в виджет)
- [x] B и C: одно превью + «Открыть все»; при пустых данных — **скрыть** с home (prefs «вкл» сохраняется)
- [x] Pro tab bar: **Главная · Расписание · Клиенты · Ещё** (home первым)
- [x] Сброс к дефолту — **с confirm-диалогом**
- [x] **C для Pro** + Pro inbox UI; контент = **уже существующие** in-app источники (без новых типов) — Q16/Q17
- [x] Следовать канону [frontend-home-виджеты-главной-mvp](../../../_telotron.ru/docs/Техдок/01-канон-mvp/frontend-home-виджеты-главной-mvp.md)
- [x] Client: пересобрать `ClientTrackerHomePage` как shell виджетов
- [x] Pro: `ProHomePage` + пункт `home` первым в `proBottomTabs`
- [x] Pro: inbox (колокольчик / лист) на **существующих** Pro in-app источниках; без новых kinds
- [x] Реализация виджетов A, B, C, G, H, I, J (`shared/home-widgets` + `widgets/home`)
- [x] Vitest / smoke; `npm run build` через Sail
- [x] Shell home для Pro → `workspace-home` (не schedule)

- Новые **типы** оповещений Pro (паритет событий с Client и т.п.) — отдельный тикет после инвентаризации.
- Виджеты D / E / F (сводка клиентов, финансы, прогресс) — позже, когда будут данные.
- Настраиваемые пункты главного меню → [идея](../идеи/главное-меню-настраиваемые-пункты.md).
- A/B дефолтов по сегменту T1/T2 (после v1).
- Произвольные пользовательские HTML-виджеты.
- Синк layout между устройствами (сервер) — после v1.
