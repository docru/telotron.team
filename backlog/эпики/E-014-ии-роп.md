# E-014 — ИИ-РОП

| Поле | Значение |
|------|----------|
| **Статус** | `planned` |
| **Приоритет** | P1 |
| **Инициатива** | [I-001 Модуль продаж](../инициативы/I-001-модуль-продаж.md) |
| **Владелец** | продукт + [AI-инженер](../../11-AI-инженер/README.md) + архитектор |
| **Связанные** | [E-010](E-010-ии-консультант-продаж.md) (пилот-фундамент) · [E-006](E-006-crm-тренера.md) · [E-008](E-008-зона-лидов.md) · [E-009](E-009-кросплатформенность.md) |
| **Канон** | [Агенты](../../11-AI-инженер/Работа/Агенты/Общее-писание-агентов.md) · [Этапы](../../11-AI-инженер/Работа/Агенты/Этапы.md) · ADR-010 · ADR-011 |

**Цель.** Встроить в раздел Pro «Поиск клиентов» **цифрового РОП + наставника**: оркестратор координирует слои; система диагностирует ситуацию, предлагает стратегию, ставит ежедневные задачи, даёт инструменты и попутно обучает основам маркетинга и продаж. Без обучения собственных моделей (Caila / готовые LLM).

**Не цель.** Замена CRM; автономные сделки без тренера; bio/мед/юр/фин-советы; обещания результатов; давление на лидов. **Автоотправка сообщений лиду от имени тренера** — только после отдельного решения (юр. + guardrails; см. идеи в `Работа/Агенты/Идеи.md`). Fine-tune foundation-моделей — не этап.

**Связь с E-010.** Пилот утреннего брифа (E-010) — **волна 1, фундамент**. E-014 наращивает поверх: не ломаем принцип «код решает, ИИ объясняет», валидацию, fallback, лимиты, PII-макросы, `ai_runs`.

### Сквозное — Поддержка тренера ([концепция](../../11-AI-инженер/Работа/Агенты/Система-поддержки-тренера.md))

Поддержка = помощь в действии, не мотивация. Уровень считает код, ИИ только формулирует в стиле тренера (`style.address`, тон). Объединено с идеей «позитивное закрепление» из [Идеи.md](../../11-AI-инженер/Работа/Агенты/Идеи.md).

**В MVP (фундамент):**
- [ ] Уровни 0–1 только: факты и видимый прогресс в брифе («за неделю — 5 ответов, 3 диалога»). Цифры и текст блока — шаблон кода, LLM чисел не пишет
- [ ] Потолок поддержки: вопрос в анкете роста задаёт стартовый потолок + переключатель «низкий / средний / высокий» в настройках (3 вопроса анкеты вместо 4–5)
- [ ] Точка расширения: `care level` тренера (пока 0–1)
- [ ] Общая таблица сигналов тренера (принял / отложил / отклонил / «спасибо, не нужно» / показанная поддержка) — та же, что для весов скоринга и карты компетенций; не поля в `ai_runs` и не в брифах
- [ ] Метрики: доля «спасибо, не нужно», удержание тренера в разделе через 2–4 недели

**После MVP:**
- [ ] Уровень 2 (внимание к состоянию: «отложил трижды») — после сбора сигналов 2–4 недели; показать юристу (профилирование тренера)
- [ ] Уровни 3–4 (отдых, «всё в порядке?») — **только после отдельного решения PO + юриста**; данных об отдыхе в продукте нет

## Acceptance

- [ ] Оркестратор — код; при сбое ИИ тренер не остаётся без результата (fallback)
- [ ] Стратегия выбирается тренером; система не навязывает одно решение без выбора
- [ ] Задачи в бриф только из разрешённых источников; ИИ не придумывает задачи
- [ ] PII в модель — через макросы / минимум; ключи API не в логах
- [ ] Лимиты вызовов и бюджет на тренера соблюдаются
- [ ] Eval / golden set для новых сценариев перед prod ([чеклист](../../11-AI-инженер/Инструкции/Чеклист-перед-AI-сервисом.md))
- [ ] Поддержка не выше потолка тренера; без имитации эмоций и мотивационных лозунгов; цифры прогресса — из кода
