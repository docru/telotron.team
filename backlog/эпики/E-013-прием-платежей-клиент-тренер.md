# E-013 — Приём платежей клиент → тренер

| Поле | Значение |
|------|----------|
| **Статус** | `planned` |
| **Приоритет** | P0 |
| **Инициатива** | [I-003 Платежи](../инициативы/I-003-платежи.md) |
| **Владелец** | продукт + разработка (+ финансы/юр. контур) |
| **Связанные** | [E-001](E-001-commerce-модуль.md); канон монетизации платформы |

**Цель.** Клиент оплачивает услуги тренеру через платформу (или контролируемый платёжный контур), с прозрачным статусом для обеих сторон.

**Не цель.** Оплата подписки/клиенто-дня платформы тренером (это E-001); полный marketplace.

## Сроки (ориентир)

| Веха | Срок | Критерий |
|------|------|----------|
| MVP приёма | январь 2027 (ориентир DEC-008) | клиент может оплатить тренеру; тренер видит статус |

## Этапы

### Этап 1 — Модель платежа
- [ ] Сущность платежа/счёта клиент→тренер
- [ ] Роли, комиссии платформы (если есть), чеки/закрывающие — по юр. решению

### Этап 2 — Провайдер и UX
- [ ] Интеграция платёжного провайдера
- [ ] Client: оплата; Pro: история и статус

### Этап 3 — Стык с CRM / договором
- [ ] Опциональная связь с модулем продаж (I-001)
- [ ] Повторные платежи / рассрочка — вне MVP, бэклог

## Acceptance

- [ ] Успешный и неуспешный платёж отражаются в Pro и Client
- [ ] E-001 (оплата платформы) не смешивается с этим контуром в учёте

## Заметки

E-001 остаётся эпиком **оплаты платформы** (клиенто-день / аддоны). Этот эпик — **B2C через тренера**.
