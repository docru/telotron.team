**Цель.** **Безголовая CRM**: домен + **контракты API**, которыми пользуются **E-008** (зона лидов), **E-010** (ИИ-консультант) и тонкий UI Pro. Контакты, статусы, заметки / следующее действие, переход «стал клиентом» в M1 — без обязательной привязки к мессенджерам.

**Не цель.** Публичная зона лида / страница записи (E-008), каналы VK/OK/MAX/TG (E-009), ИИ-чат и план «7 дней» (E-010). Не «освой воронку» / Kanban как продукт.

## Архитектура (рамка)

```text
E-008 (зона лидов) ──create/update──► E-006 CRM API / domain
E-010 (ИИ)         ──read/write──────► E-006 CRM API / domain
Pro UI (тонкий)    ──тот же API──────► E-006 CRM
E-006 ──«стал клиентом»──► M1 (invite / Client)
E-006 ──опционально──────► M2 (пробная запись) — не блокер MVP CRM
```

## Сроки (ориентир)

| Веха | Срок | Критерий |
|------|------|----------|
| MVP CRM (API + тонкий Pro) | октябрь — середина ноября 2026 | контакты и статусы в продукте; E-008/E-010 не блокируются |

## Этапы

### Этап 1 — Модель, статусы, API, отладочный UI
- [ ] Модель контакта (единая + «откуда»)
- [ ] Этапы: новый → в работе → клиент → бывший | отказ
- [ ] HTTP/доменные контракты для Pro (отладка) / E-008 / E-010
- [ ] Простой список/карточка **только для отладки** (потом ведение через ИИ)

### Этап 2 — Действия
- [ ] Заметки / следующее действие (пишут тренер и E-010)
- [ ] Связь «стал клиентом» с M1; автосклейка дублей по телефону

### Этап 3 — Готовность к соседним эпикам
- [ ] Точки расширения под зону лидов (E-008) и каналы (E-009)
- [ ] События/контракты для ИИ (E-010) — без внедрения модели в этом эпике

## Acceptance

- [ ] Тренер создаёт/ведёт контакт и меняет статус через Pro (тот же API)
- [ ] E-008 может создать/обновить контакт без UI CRM
- [ ] E-010 может читать статусы и писать заметки/следующее действие по контракту
- [ ] Соседние эпики I-001 не блокируются отсутствием базовой CRM

## Заметки

- Скоуп сужен до CRM; поиск/зоны/каналы/ИИ — E-008…E-010.
- 2026-09-20: зафиксирована **безголовая** CRM (сервис + интерфейсы).
